# Worker disk budgets

This Linux/Node 22 runner shares a disk admission queue across independent invocations. It requires `df`, `du`, and `flock`; no package installation or service manager is needed. Use one private state directory on the filesystem being budgeted for every participating runner. Existing workers outside this runner are measured by free disk space but cannot be preempted.

```sh
node scripts/worker-runner/cli.mjs run \
  --state-dir "$HOME/.local/state/worker-runner" \
  --id review-001 --work-dir "$PWD" --budget 1G --priority normal \
  -- bash -c 'echo finished'
node scripts/worker-runner/cli.mjs status --state-dir "$HOME/.local/state/worker-runner"
```

The default reservation is 1 GiB and disk floor is 5 GiB. Admission requires free bytes minus remaining reservations of running workers to cover the next budget plus floor. Remaining reservation is the original budget minus observed growth in the work directory and owned temporary directory, clamped at zero. This is an estimate rather than a filesystem quota. The strictest floor requested by any queued or running worker applies to admission and preemption. Priorities are `high`, `normal`, `low`, or numeric (larger first); ties use entry order. A queue head larger than filesystem free space minus the floor is skipped so fitting rounds can progress even while other rounds are active. A head that fits that total capacity but currently waits for reservations retains its place. Priority always precedes a resumed round's front flag; the flag only advances rounds within the same priority.

`--budget` overrides an instruction file supplied with `--instruction FILE`. JSON accepts `disk_budget` and `disk_priority`; ordinary text accepts separate lines `worker-disk-budget: 4G` and `worker-disk-priority: high`. Explicit CLI priority wins. `--default-budget 4G` sets a wrapper's fallback after instruction values. Web builds might reserve 4G while reviews reserve 1G. `--floor`, `--timeout SECONDS` (zero means unlimited), and `--poll-ms` configure the floor, elapsed admission-to-completion limit (including queued waits) and polling interval. Units K/M/G/T use powers of 1024.

Each attempt creates the conventional temporary root `/tmp/<round-name>`. If the default temporary base is on a different filesystem from the state directory, the runner uses `<stateDir>/runs/<round-name>` automatically. Explicit `--temp-base BASE` or `WORKER_RUNNER_TEMP_BASE` selects `<BASE>/<round-name>` and must share the state filesystem. The default name is `--id`; wrappers with a different round name pass `--temp-name NAME`. `WORKER_RUNNER_TMP_ROOT` points to that root; `TMPDIR`, `TMP`, and `TEMP` point to its `tmp` child. The ownership marker stays outside TMPDIR, so clearing temporary contents cannot remove it. Both paths belong to the same measured attempt. Existing paths are rejected rather than adopted. Names containing traversal, separators, or unsafe components and symlink ancestors are rejected. Cleanup confirms process-group absence again after a short settling delay, then removes only the owned root without following internal symlinks; work directories, results, commits, logs, and done markers remain durable. Keep the state directory private and do not rename owned roots or their ancestors.

Wrappers should tell workers to keep temporary files, caches, and comparison copies in the supplied TMPDIR. Registration creates a new child directory beneath the current root; existing directories and outside paths are rejected:

```sh
node scripts/worker-runner/cli.mjs register --state-dir "$WORKER_RUNNER_STATE_DIR" \
  --id review-001 --path "$WORKER_RUNNER_TMP_ROOT/comparison"
```

`WORKER_RUNNER_STATE_DIR` configures the default state directory; explicit `--state-dir` takes precedence.

Success, failure, timeout, and catchable signals all wait for the worker process group to exit, remove the owned attempt directory, then release the reservation. An independent watchdog handles an uncatchable supervisor kill, including killing orphan descendants before cleanup; every invocation also reconciles dead supervisors. State writes are atomic and serialized across processes. Ownership is persisted before temporary-directory creation; a launch handshake prevents the payload from running before its process group is committed to state. Process identities retain legacy numeric Linux start-time tokens, with separate kernel boot ID and PID namespace fields. This preserves compatibility with already running legacy supervisors. Live legacy owners and their reservations remain active; verified process-group identities are populated without abandoning their rounds. Cross-namespace ownership is rejected, and identity metadata failures fail closed before admission. Known group members anchor orphan recovery after a leader exits, and the launch process drains background writers before exiting normally. A kernel-backed `flock` lease is held through a private subprocess pipe; closing the pipe or killing the supervisor releases the lock without stale-lock races. Entries from another boot or PID namespace retain their reservations and block new admission until an operator verifies and recovers them; the runner never blindly deletes their roots.

The runner reads filesystem-wide free space with `df` on every scheduler tick (default polling delay one second; `df` timeout 1.5 seconds) across `stateDir`, `workDir`, and all worker runtime mounts (`/`, `~`, `~/.gemini`, `~/.claude`, `~/.cache`, `$TMPDIR`, `/tmp`; override via `--disk-paths` or `WORKER_RUNNER_DISK_PATHS`) and enforces the floor against the tightest mount (`scripts/lib/disk-free.mjs`). Work, state, and the temporary root must share a filesystem. Usage samples use asynchronous `du` outside the shared lock at the smaller of one second and the configured polling delay, with a one-second timeout per concurrent sample. Pressure triggers a refresh of all active rounds before victim selection, so an early sample of an empty directory does not hide a later writer. Lock acquisition has a two-second timeout. These are sampled estimates, not hard quotas: a rapid writer can cross the floor between observations.

Single worker launch path and `work-watch` registration

Use `scripts/worker-runner/spawn-worker.mjs` as the standard launcher so every worker passes the multi-mount disk floor check, runs inside a transient `systemd-run --user` unit (or `--foreground`) wrapped by `worker-runner/cli.mjs`, and auto-registers `{ unit, resultFile, watchDirs, role }` into `.agents/work/work-watch/registry.json`:

```sh
node scripts/worker-runner/spawn-worker.mjs \
  --id fix-001 --role infra --work-dir "$PWD/run-001" --watch-dir "$PWD/run-001" \
  --result-file "$PWD/run-001/result.md" --stall-min 15 \
  -- codex exec "implement fix"
node scripts/work-watch.mjs watch --root "$PWD"
```

`scripts/work-watch.mjs` treats non-empty `resultFile` creation as completion (`[일꾼 감시] 일꾼 끝`), and wakes the spawning role's `wakeDir` when output files in `watchDirs` show no progress for `--stall-min` minutes (`[일꾼 감시] 진도 없음`) or when the worker unit/PID exits before writing `resultFile` (`[일꾼 감시] 유닛 죽음`). Direct detached shell launches (`nohup`, `setsid`, `&`, `tmux -d`, `screen -dm`) of `agy`, `codex`, `claude -p`, and `muse exec` are blocked by the PreToolUse bash guards.

When observed use exceeds twice the round budget, the runner stops the worker and reports `budget-killed`; it does not restart that writer. When filesystem free space falls below the floor, it refreshes active round usage and first stops the round with the largest observed excess over budget. An over-budget floor victim also fails without automatic restart. When the writer cannot be identified because it wrote outside its conventional root and work directory, the fallback chooses the most recently started round, then the largest reservation and later entry order. This is a heuristic: filesystem-wide `df` detects outside writes but cannot attribute them, and unrelated processes can cause pressure. The runner cannot clean an unowned outside path. A stopped round with no measured budget excess retains its place within its priority class and resumes with `WORKER_RUNNER_RESUME=1`; commands must continue from durable checkpoints. SIGTERM is followed by SIGKILL after five seconds. A stopping round older than ten seconds emits human attention once and stops blocking admission or further emergency victims; its reservation remains charged until its process group exits. Only verified runner-owned process groups receive signals.

Wrappers using an existing done-marker protocol can pass `--done-file FILE --done-grace SECONDS` (default 300). Only a marker modified since admission is recognized; a marker from an earlier invocation is ignored. A nonzero worker exit still fails even if a fresh marker appeared. After a fresh marker appears and grace expires, the worker group is stopped and the invocation exits successfully. Use a fresh marker per round. A preempted round never completes its invoking wrapper until its resumed attempt finishes.

Status prints free bytes, total remaining reservation, and running/stopping/queued rounds as one compact JSON view. The most recent 100 terminal outcomes remain in the state file; active rounds are always retained. Cleanup failures emit `cleanup-failed`, retain `cleanupRoot` and `cleanupError` beyond history pruning, and appear in status as `cleanupPending`. Reconciliation makes at most five total cleanup attempts, backing off 1, 2, 4, then 8 seconds (delay capped at 30 seconds). A permanent ownership/symlink/EPERM error or exhausted retries emits one `human-attention` event per entry; a preempted queued round then ends as failed. Pending roots keep the same ID blocked until an operator resolves them, without leaving its caller queued forever. Cleanup never aborts unrelated rounds or resumes before cleanup succeeds; undeleted bytes remain counted by filesystem free space. The runner repairs owned root and marker permissions before checking the token and restores directory permissions through no-follow directory descriptors anchored at `/proc/self/fd`, including every parent during traversal. Descriptor traversal has a depth limit. Deletion retries concurrent `ENOTEMPTY` writes with at most five retries and 100 ms linear backoff, then makes one fresh descriptor repair pass and a final deletion attempt; one native retry sequence waits at most 1.5 seconds. Tree size and filesystem latency still affect total cleanup time. Persistent failures enter the bounded cleanup policy above. Readable directories still have their children repaired after a chmod EPERM. Missing roots return immediately. Work usage excludes the nested state directory and all recorded worker roots, and the first work baseline survives preemption. Transient supervisor errors use capped exponential retry delays and suppress duplicate messages. State loss or corruption stops supervision and emits one `human-attention` event; the owned worker is stopped safely. Unchanged transactions do not rewrite state. Structured start, stop, budget-exceeded, recovery, and end events include the round ID. Each run emits only its own events. Recovery of another round is recorded in the state directory supervisor log, never in the caller’s worker log. Pass `--event-log FILE` to keep supervisor JSON separate from worker output; otherwise events go to stderr. A wrapper combining stdout/stderr must use this option to preserve result extraction. `muse-result.sh LOG RESULT DONE CHILD_EXIT` provides fallback result extraction, excludes legacy supervisor JSON, and returns nonzero when the result is empty or the child failed. Full command output stays on the caller's stdout/stderr; configure log retention in the invoking service.

Run deterministic tests with `node --test scripts/worker-runner/*.test.mjs`. Unit tests use fake free-space values, worker effects, and cleanup adapters. CLI integration tests launch only their own small local fixture processes and clean their own temporary directories; no existing workers or state directories are used. Set `TMPDIR` to a private test parent to keep every fixture underneath it. Tests also accept an unset `TMPDIR` using the operating system temporary-directory fallback. The repository `pnpm test` includes this suite.

State format version and mixed releases

State contains a format version. A runner that sees a newer unknown format refuses new admission and watch supervision without rewriting the file; status reads it without mutation. This protects newer state from older supervisors that implement the version check. It cannot retrofit that check into an already running historical binary. Numeric owner tokens therefore remain compatible with historical supervisors that lack the check. Do not introduce incompatible token changes while those supervisors are active. Tests launch the historical CLI against isolated fixture state and verify both rounds survive mixed execution.

Pinned deployment and rollback

The server uses only a pinned detached worktree. A commit in a development checkout does not change the server. Updating the pinned release means moving that detached worktree to the exact commit that passed review. Preserve the preceding commit as the rollback target. Historical 7134268 supervisors reject abandoned conventional roots created by this release and can kill their own payloads during reconciliation. Stop admitting new rounds and wait for every old run supervisor and detached watch to finish naturally before replacement. Do not run the new release against shared state during this drain. Preserve state and inventory orphan attempt directories for separately authorized cleanup; never erase records to claim free space. Deploy the full reviewed lineage (including prior process identity and exception isolation changes), rather than cherry-picking only the cleanup increment. Then move the pinned worktree, verify the runner and optional helper exist, and finally apply the adapter changes. Adapter calls to optional helpers must retain a fallback for older releases. Roll back the adapter first, then move the pinned detached worktree back to the preceding reviewed commit. Repository tests never modify a deployed pinned worktree or live state directory.
