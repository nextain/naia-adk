# Issue #16 — Phase 2 small-experiment and composition plan

Date: 2026-07-30
Status: planned after the phase-1 usable profile checkpoint

## Objective

Build reusable routing knowledge from small experiments, then test whether the complete `balanced` or `economy` development process costs less than the `control` process without unacceptable quality loss. Model names are replaceable bindings; role profiles and safety guards remain stable.

## Evidence ladder

1. **Atomic capability:** one bounded ability, one external scorer, no orchestration claim.
2. **Role qualification:** repeated atomic evidence supports a conditional role rule and its forbidden conditions.
3. **Profile composition:** qualified roles execute the same complete issue from request interpretation through integration.
4. **Operational decision:** only complete, reviewable journals with current price evidence can change the recommended profile.

Evidence never skips a level. A cheap atomic worker result cannot establish total-system savings.

## Initial atomic experiments

|---|---|---|---|---|
| AX-01 | exact code output | prompt, cases, scorer | exact pass and tokens | bounded implementation threshold |

| AX-06 | Korean mirror translation | fixed source and glossary | semantic/structural fidelity | translator eligibility |
| AX-07 | nested context recovery | fixed repository tree | correct rule precedence | context complexity threshold |
| AX-08 | requirement atomization | fixed source request | obligation recall and trace | orchestrator-only triggers |
| AX-09 | bounded multi-file change | fixed small repository | tests, scope discipline, rework | Terra delegation boundary |
| AX-10 | integration judgment | conflicting valid patches | correct synthesis and regressions | Sol integration requirement |

Each experiment records ambiguity, number of touched files, context depth, validator strength, risk, model binding, exact configuration, quality, tokens, billed cost, wall time, retries, and failure class. At least one negative or boundary case is required before a role rule is accepted.

## Theory record

Every accepted observation becomes a record with:

- observation and immutable evidence digest
- falsifiable hypothesis
- allowed task conditions
- forbidden conditions
- current qualified bindings
- confidence and known counterexamples
- price/model/provider evidence expiry
- next experiment that could disprove the rule

Example: “When the mutation scope is bounded and an exact test oracle exists, a qualified bounded worker may replace the frontier worker. Unbounded design and integration are forbidden.”

## Profile comparison

Run the same representative issue set through:

1. `control`: all-Sol reference with independent executions.
2. `balanced`: Sol orchestration/integration plus exact-validated Luna bounded implementation, with Terra as the bounded fallback and focused tester.
3. `economy`: the same safety boundary plus only later evidence-qualified lightweight work.

Every trial includes request interpretation, task decomposition, implementation, testing, independent adversarial review, correction, context synchronization, and integration. Account for all orchestrator, worker, handoff, retry, review, rework, translation, and integration consumption. Report completed-issue cost, final quality, first-pass rate, defects found, duplication, context loss, and wall time.

## New-model reevaluation

A new model or material provider/price/version change triggers only the atomic experiments for its intended roles. The binding stays disabled until identity, usage, price, quality, and failure evidence pass. A binding change then reruns the affected profile comparison; it does not alter profile semantics. Missing or expired evidence fails closed to the prior qualified binding or `control`.

## Review and publication gates

- Preserve raw journals and provider receipts outside candidate access but in an auditable evidence store.
- Use the same frozen task revision across compared profiles.
- Require two consecutive unchanged-digest cross-review rounds. Each round uses independent Claude, Gemini, and a third non-Anthropic/non-Google reviewer whose exact model identity is pinned in the receipt; failures or unavailable reviewers are not CLEAN.
- Publish allowed and forbidden claims together in issue #16.
- Do not change the default recommendation from `balanced` until full composition evidence exists.
