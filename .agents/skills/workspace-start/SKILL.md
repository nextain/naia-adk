# 작업 공간 시작

## 목적

사람은 AI와 이야기하며 일합니다. 설정, 최신 내용 받기, 대시보드 띄우기는 AI가 대신합니다. 이 스킬은 그 순서를 정합니다. 끝나면 사람은 브라우저 주소 하나와 첫 문서만 받습니다.

## 순서

### 1. 맨 위 폴더인지 확인

현재 폴더에 `AGENTS.md`와 `package.json`이 있고, `package.json`에 `adk:setup` 스크립트가 있어야 합니다. `projects/` 안에서 띄워졌다면 사람에게 맨 위 폴더에서 다시 띄워 달라고 한 줄로 알립니다.

### 2. 필요한 도구 확인

`git --version`, `node -v`(22 이상), `pnpm -v`(9 이상)를 확인합니다. 빠진 것이 있으면 무엇을 설치해야 하는지 알리고, 설치 명령을 실행해도 되는지 사람에게 묻습니다. 사람의 허락 없이 시스템에 무언가를 설치하지 않습니다.

### 3. 회사 연결

`data-company/*/adk-company.json`이 하나도 없으면 아직 회사 문서를 받지 않은 상태입니다.

1. 사람에게 회사 문서 저장소 주소를 묻습니다. 인자로 받았으면 묻지 않습니다.
2. `pnpm install`을 실행합니다.
3. `pnpm adk:setup -- --company <주소>`를 실행합니다.
4. 저장소를 받지 못했다면(권한 없음 등) 오류 한 줄과 함께, 누구에게 어떤 권한을 받아야 하는지 사람에게 알립니다.

### 4. 최신 받기

회사 연결이 이미 되어 있으면 `pnpm adk:setup -- --pull`을 실행합니다. 고치던 파일이 있어서 건너뛴 저장소가 있으면, 그 저장소 이름과 이유를 짧게 알립니다. 건너뛴 저장소를 강제로 되돌리거나 덮어쓰지 않습니다.

### 5. 대시보드 띄우기

1. `http://localhost:3142/docs`가 응답하는지 확인합니다. 응답하면 이미 떠 있는 것이니 새로 띄우지 않습니다.
2. 응답하지 않으면 맨 위 폴더에서 `./start.sh`(Windows는 `start.bat`)를 백그라운드로 실행합니다.
3. `/docs`가 응답할 때까지 최대 1분 기다립니다.
4. 3141이나 3142 포트를 다른 프로그램이 쓰고 있으면, 그 프로그램을 끄지 않습니다. 어떤 프로그램이 쓰고 있는지만 사람에게 알립니다.

### 6. 사람에게 알리기

짧게 세 가지만 말합니다.

- 대시보드 주소 `http://localhost:3142/docs`. "작업" 탭에서 진행 상황을 볼 수 있다는 것도 함께 알립니다.
- 처음 온 사람이면 읽을 첫 문서. 회사 문서의 온보딩 첫 문서입니다.
- "무엇을 할지 말씀해 주세요."

명령어 목록이나 설정 과정의 긴 출력은 보여 주지 않습니다.

## 이후 일하는 방식

- 사람이 말로 맡긴 일은 회사 절차에 따라 AI가 처리합니다. 다른 기기나 다른 AI에게 넘길 일은 AI가 작업 대기열에 올립니다.
- 사람이 정해야 할 일이 생기면 AI가 문서로 정리하고 확인을 요청합니다. 요청은 작업 탭 "확인 필요" 칸에 뜹니다.
