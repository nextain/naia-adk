# 제안서 작성

공식 양식을 역으로 분석한 뒤, 출처가 확인된 사실만으로 제안서를 작성하고 심사자 관점의 검토와 보강을 반복한다. 확인되지 않은 정보는 추측하지 말고 빈칸과 사용자 확인 목록으로 남긴다.

## 불변 규칙

1. 수치, 실적, 고객, 매출, 인력, 투자, 특허, 인증, 계약, 일정, 제품 상태를 지어내지 않는다.
2. 계획·목표·예상을 달성 실적으로 바꾸지 않는다.
3. 회사·프로젝트 내부 자료를 먼저 찾고, 외부 조사가 가능한 시장·정책·경쟁 정보만 신뢰할 수 있는 출처로 보강한다.
4. 모든 핵심 주장에 근거 상태를 붙인다: `내부 확인`, `외부 확인`, `사용자 제공`, `계산`, `미확인`.
5. 미확인 값은 `[[확인 필요: 질문]]`으로 표시하고 최종 사용자 확인 목록에 모은다.
6. 공식 양식의 순서, 제목, 표, 분량, 제출 형식, 필수 증빙을 임의로 바꾸지 않는다.
7. 공고가 원본 HWP 사용을 강제하면 HWPX는 검토·이식용으로만 만들고, 제출 형식 위험을 사용자에게 명시한다.

## 시작 전

- HWP/HWPX/PDF/DOCX/XLSX/PPTX는 먼저 `read-doc` 스킬로 읽는다.
- PDF 추출 결과가 비거나 깨지면 모든 페이지를 이미지로 렌더링하여 육안 판독 또는 OCR을 수행한다.
- 작업 저장소의 `AGENTS.md`와 필수 컨텍스트를 먼저 읽는다.
- 같은 사업의 기존 초안, 회사 현황, IR, 특허·인증, 재무·인력 증빙을 확인한다.
- 작업 산출물 형식은 [work-products.md](references/work-products.md)를 따른다.

## 1. 양식을 마크다운으로 분해

공고와 작성 양식을 빠짐없이 마크다운으로 옮긴다. 원문의 순서와 계층, 표 열, 체크박스, 분량 제한, 증빙 요구를 보존한다. 각 항목에 심사 질문, 필요한 사실·수치, 평가 관점, 내부·외부·사용자 자료 후보, 필수 증빙을 기록한다. 양식에서 유추한 평가 관점은 `추론`이라고 표시한다.

산출물: `양식 지도`와 `조사 질문 목록`.

## 2. 회사와 프로젝트 정보 수집

1. 회사 컨텍스트, 기존 제안서, IR, 제품 문서, 계약·매출·인력·특허·인증 자료를 검색한다.
2. 프로젝트의 현재 상태, 검증 결과, 고객 가치, 일정, 담당 인력, 비용과 위험을 수집한다.
3. 시장 규모, 정책, 경쟁사, 산업 동향은 최신 외부 자료로 조사하고 출처 URL과 확인일을 기록한다.
4. 충돌하는 값은 임의로 하나를 고르지 말고 충돌 상태로 표시한다.
5. 양식 항목별 후보를 `근거 장부`에 연결한다.

민감한 내부 자료는 공개 검색이나 외부 서비스에 전송하지 않는다.

## 3. 간략한 제안서 흐름 작성

공식 양식 순서 안에서 `회사·문제 맥락 → 검증된 역량 → 제안 내용 → 차별성 → 실행 가능성 → 측정 가능한 목표 → 지원 필요성·기대효과` 흐름을 만든다. 각 단락의 핵심 주장, 근거, 남은 빈칸을 표시하고 근거가 부족한 항목은 문장으로 메우지 않는다.

## 4. 데이터에 기반하여 보강

- 가장 강한 내부 근거를 우선 배치하고 관련 없는 실적은 덜어낸다.
- 숫자는 단위·기준연도·산식·출처를 함께 기록한다.
- 외부 자료는 원 출처 또는 공공·공식 자료를 우선한다.
- 경쟁 비교는 동일 기준으로 작성하고 확인할 수 없는 우월 표현을 쓰지 않는다.
- 목표치는 기준값, 달성 수단, 측정 방법을 함께 제시한다.

## 5. 심사자 관점으로 적대 검토

다음을 처음 보는 심사자처럼 검사한다.

- 자격·제출 요건과 양식 항목을 모두 충족하는가
- 핵심 주장이 증거로 뒷받침되는가
- 기술·사업 차별성이 구체적이고 비교 가능한가
- 인력·일정·예산·목표가 현실적인가
- 회사 현황, 표, 본문, 첨부 증빙의 숫자가 일치하는가
- 지원 필요성과 지원 후 성과의 인과관계가 분명한가
- 과장, 모호한 표현, 근거 없는 최상급이 있는가
- 예상 반론에 답했는가

발견 사항을 `차단`, `중요`, `경미`로 분류하고 위치, 문제, 필요한 근거, 수정 방향을 기록한다.

## 6. 조사·보강 반복

검토 결과를 `내부 자료로 해결`, `외부 조사로 해결`, `사용자 확인 필요`로 나눈다. 근거 장부와 원고를 갱신한 뒤 다음 조건을 모두 만족할 때까지 적대 검토를 반복한다.

- 근거 없는 확정적 주장이 없다.
- 모든 양식 항목이 작성되었거나 `미확인`으로 명시되었다.
- 모든 수치가 출처 또는 계산식을 가진다.
- `차단` 사항이 없고, 남은 `중요` 사항은 사용자만 답할 수 있는 질문으로 정리되었다.

사용자 질문에는 `필요한 이유`, `들어갈 항목`, `답의 단위·형식`을 함께 제시한다.

## 7. 원본 양식 기반 HWPX 납품

1. 원본 HWP를 복사본 HWPX로 변환하여 표·스타일·머리말·쪽 구성을 보존한다.
2. Windows에서 한컴오피스와 `FilePathCheckerModuleExample` 보안 모듈이 설치·등록되어 있으면 다음 스크립트를 사용한다. 모듈이 없거나 등록 경로가 깨져 있으면 자동화하지 말고 수동 이식 경로를 사용한다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/convert_hwp_to_hwpx.ps1 `
  -SourcePath "공식양식.hwp" -OutputPath "제안서_작성본.hwpx"
```

3. 변환본에 확정된 내용만 이식한다.
4. `read-doc`으로 재추출하여 제목 순서, 표, 핵심 문장, 숫자, 빈칸을 원고와 비교한다.
5. 가능하면 전 페이지를 PDF 또는 이미지로 렌더링해 잘림, 표 넘침, 글꼴, 페이지 수를 확인한다.
6. HWPX, 근거 장부, 미확인 질문 목록, 제출 전 점검 결과를 함께 납품한다.

자동 변환이 불가능하면 원본 HWP를 훼손하지 말고, 완성 원고와 셀별 이식 지시서를 제공한다.
