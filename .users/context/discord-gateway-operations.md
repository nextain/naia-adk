# Discord gateway operations

## 세션 식별과 완료 판정

세션의 표시 이름은 사람이 찾기 위한 이름입니다. 라우팅과 권한은 인증된 연결과
고유한 세션·작업 식별자로 판정합니다. 대화에서 다른 이슈를 언급했다고 기존 연결을
바꾸지 않으며, 자동 실행 지시문을 새 세션 이름이나 작업 항목으로 사용하지 않습니다.
프로젝트에서 이슈 단위 라우팅을 사용하면 저장소 소유자·저장소·이슈 번호를 함께
식별하고, 개인 세션에는 로컬 정책에 없는 이슈 의무를 새로 부과하지 않습니다.

실행 종료, 응답 전달, 사용자 목표 달성은 서로 다른 증거입니다. 실행이 끝났다는
기록으로 전달 성공이나 이슈 닫힘을 추정하지 않습니다. 사람의 승인·확인 대기는
워커 종료만으로 지우지 않습니다. Discord의 일반 메시지와 답글(type 0, 19)만
대화로 판정한 다음 작성자를 확인합니다. 이름 변경 같은 시스템 이벤트는 답변이나
새로운 대화 문맥으로 세지 않습니다.

기존 데이터베이스의 트랜잭션을 사용하고 별도의 JSON 장부가 필요하면 모든 쓰기
프로세스가 읽기·수정·원자적 교체 전체를 같은 잠금으로 묶어야 합니다. 로컬 파일
잠금은 여러 호스트를 조정하지 못합니다. 메타데이터 감사는 읽기 전용으로 유지하고,
실제 수정은 변경 전 메타데이터와 마지막 메시지를 다시 비교한 뒤 수행합니다.
요청 제한 대기 후에도 재확인하며, 보관된 스레드는 열기→이름 변경→재보관 순서로
처리합니다. 부분 실패는 단계별 적용 기록과 현재 값 비교를 사용해 자기 변경만
되돌리고 메시지를 삭제하지 않습니다.

이 항목은 어댑터 도입 요구사항입니다. 모든 백엔드에 이미 구현됐거나 현재 봇에
배포됐다는 뜻이 아닙니다. 서로 다른 저장소의 같은 이슈 번호, 교차 참조, 시스템
이벤트, 실행 완료 후 전달 대기, 사람 확인 대기 보존, 동시 쓰기, 대기 중 외부 수정,
부분 실패 복구를 해당 어댑터에서 확인해야 합니다. 프로젝트별 이슈 장부와 스레드
정책은 naia-pj-adk 프로젝트 어댑터가 소유하며, 개인 식별자·자격증명·실시간 상태는
공유 컨텍스트로 옮기지 않습니다.
