# Discord gateway operations

## Session identity and completion evidence

Display names help people find a session. Routing and authority use authenticated
bindings and stable native session or job identifiers. Cross-references do not
retarget an existing session. Synthetic dispatch prompts must not become session
titles or new work items. Project issue routing uses repository owner, repository
and issue number together; personal sessions do not acquire an issue requirement
that their local policy never declared.

Execution termination, confirmed delivery and completion of the user's goal are
separate evidence. A terminal worker does not prove delivery or issue closure and
must not clear a pending human approval or verification. Filter Discord message
types to normal messages and replies (0 and 19), then check the author. System or
unknown events must not discharge reply obligations or become conversation input.

Use the existing transactional database. If an adapter maintains external JSON,
all writers must share a lock across read, modification and atomic replacement.
A local file lock does not coordinate hosts. Keep audits read-only. Before each
metadata write, compare current metadata and the latest message with the reviewed
preimage, including after rate-limit waits. Rename archived threads by opening,
renaming and restoring the archive state. On partial failure use step receipts
and current-value checks to restore only your own changes; preserve all messages.

These are adapter adoption requirements, not claims that every backend already
implements them or that a live bot was deployed. Verify cross-references, equal
issue numbers in different repositories, system events, delivery pending after
execution ends, preserved human waits, concurrent writes, drift during a wait and
partial rollback in the adopting adapter. Project issue tracking and thread policy
belong to the naia-pj-adk project adapter. Private identifiers, credentials and
live state remain outside shared context.
