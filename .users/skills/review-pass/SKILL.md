# 리뷰 패스

`.agents/skills/review-pass/SKILL.md`의 사람용 핵심 규칙입니다.

## 핵심 절차

1. planning, development, test, integration 단계에 맞는 검토 관점을 선택합니다.
2. 검토자는 구현자와 다른 역할·세션·실행으로 같은 수정본을 읽습니다.
3. 확인된 범위 내 결함은 조정자가 자동 수정하고 다시 검토합니다.
4. 연속 Clean 기준과 원요청·보존 계약의 차단 조건을 모두 충족할 때까지 반복합니다.

## CONTESTED 처리

`CONTESTED` 발견 사항을 즉시 사용자 질문으로 바꾸지 않습니다.

1. 독립 중재자(arbiter)를 우선 실행합니다.
2. 원문 요청, 요구사항, 실제 코드, 테스트와 불변 근거를 다시 대조합니다.
3. 근거로 확인된 범위 내 결함은 자동 수정·재검토합니다.
4. 중재자를 즉시 사용할 수 없으면 다른 독립 실행으로 재시도합니다.
5. 근거 검증 뒤에도 설계·사업·제품·범위·권한 또는 비가역·외부영향 결정이 남을 때만 사용자에게 묻습니다.

## 보존 관련 거부권

기존 기능의 교체·제거·비활성화·우회·이전 권한은 중재자가 만들어낼 수 없습니다.
해당 거부권은 기존 기능 복원, 누락 근거 보완, 또는 이름이 명시된 정확한 사용자 권한으로만
해소합니다.

## 모든 단계의 필수 산출물 경계

- `context_output_separation`: 배경·참고·예시·내부 문구는 명시적인
  `derive`, `quote`, `require` 권한 없이 코드·UI·대외 문서 내용이 될 수 없습니다.
- `audience_surface_fit`: 산출물 단위의 종류, 독자, 노출 표면이 실제 소비자와
  맞는지 확인합니다.
- `unjustified_product_surface`: 기존 표면은 비오탐으로 보호하되, 새 공개·제품
  표면에는 목표 근거와 콘텐츠 출처 권한이 모두 있어야 합니다.

## 완료 기준

- 단순한 검토자 불일치만으로 작업을 멈추지 않습니다.
- 독립 중재와 원출처 검증 기록을 남깁니다.
- 실제 중요한 사용자 결정만 별도로 보고합니다.
