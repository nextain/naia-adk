# Naia ADK

**AI কোডিং এজেন্টদের কাজ করার জন্য আগে থেকে গুছিয়ে রাখা কর্মক্ষেত্রের কাঠামো।**

আপনি যখন Claude Code বা Codex-এর মতো AI কোডিং টুল ব্যবহার করেন, প্রতিটি টুল
নিজের নিয়ম-ফাইল আলাদা জায়গায় রাখে, আর «এই নথি কি প্রকাশ করা যাবে?» বা
«স্কিল কোথায় যাবে?»—এমন প্রশ্নের উত্তর জোড়াতালি দিয়ে মেলে। Naia ADK এই
কাঠামো আগে থেকেই তৈরি করে দেয়। নতুন ল্যাপটপে যেমন প্রথমে ডেভেলপমেন্ট পরিবেশ
সাজান, তেমনি এটি AI এজেন্টের হাতে শুরুর জন্য গোছানো ডেস্ক তুলে দেয়। সাথে একটি
ড্যাশবোর্ডও আছে, যাতে কর্মক্ষেত্রের অবস্থা এক নজরে দেখা যায়।

## ৫ মিনিটে চালু করুন

আপনার **Node 22+** এবং **pnpm 9+** লাগবে।

```bash
pnpm install    # install workspace dependencies
pnpm dev        # run the API server (:3141) and dashboard (:3142) together
```

ড্যাশবোর্ড দেখতে ব্রাউজারে `http://localhost:3142` খুলুন। সাথে সাথে তিনটি জিনিস
দেখা যায়:

- **Workspace** — প্রকল্প ও সাবমডিউল, ফাইল-বৃক্ষ, এবং প্রতিটি আইটেমের প্রকাশ
  স্তর।
- **Skills catalog** — এই কর্মক্ষেত্রে নিবন্ধিত স্কিলগুলোর তালিকা ও তাদের
  বিষয়বস্তু।
- **Settings / monitoring** — সার্ভার কনফিগারেশন, ক্লায়েন্ট অবস্থা, ডেটা
  ডিরেক্টরি।

ড্যাশবোর্ড API সার্ভারে (পোর্ট 3141) শুধু নথি-ভিউয়ের `/api/portal` অনুরোধ
পাঠায়। দুটির মধ্যে একটিমাত্র চালাতে `pnpm dev:server` (→ 3141) বা
`pnpm dev:dashboard` (→ 3142) ব্যবহার করুন। চালু-স্ক্রিপ্ট `./start.sh`
(Linux/macOS) ও `start.bat` (Windows) দুটোই `pnpm dev` চালায়। সার্ভার CLI
`--port`, `--host` ও `--root` নেয়; যেমন অন্য কর্মক্ষেত্র দেখাতে
`pnpm serve -- --root /path/to/workspace` দিন।

## ভেতরে যা আছে

### কর্মক্ষেত্রের কাঠামো

এটি AI এজেন্টকে সবকিছুর নির্দিষ্ট জায়গাসহ ডিরেক্টরির সেট দেয়, যাতে সে সাথে
সাথে কাজ শুরু করতে পারে। AI-মুখী প্রসঙ্গ থাকে `.agents/`-এ (ইংরেজি, JSON/YAML)।
মানুষের পড়ার নির্দেশিকা থাকে `.users/context/` (কোরীয়) ও `.users/context/en/`
(ইংরেজি)-এ। এই আয়না আংশিক, পূর্ণ অনুলিপি নয় — এতে শুধু সেই নথিগুলো, যা মানুষের
পড়া দরকার (যেমন স্কিলের আদি রূপ `.agents/skills/`-এ, আর কয়েকটি মাত্র
`.users/skills/`-এ প্রতিফলিত)। স্কিল, ডেটা ও প্রকল্প—সবার নির্ধারিত জায়গা
আছে, তাই যে টুলই খুলুক কর্মক্ষেত্র একই রকম দেখায়।

### ড্যাশবোর্ড ও API

একটি Next.js ড্যাশবোর্ড কর্মক্ষেত্রটি চোখে দেখে পরিচালনা করে, পেছনে Fastify API
সার্ভার। ওপরের নেভিগেশনের **Docs** (`/docs`) ও **Work** ট্যাব কোম্পানির ভাগ করা
নথি ও সহযোগ-বোর্ড এক জায়গায় দেখায়, আর
`pnpm adk:setup -- --company <repo-url>` কোম্পানি-নথি ও প্রকল্প রেপো এক ধাপে
বসিয়ে দেয়। সেটআপ ও ব্যবহারের বিস্তারিত দেখুন
[অনবোর্ডিং নির্দেশিকায়](docs/guides/onboarding.en.md)
([한국어](docs/guides/onboarding.ko.md))।
আর্কিটেকচার, চুক্তি ও বাস্তবায়ন-প্রমাণ নথিভুক্ত করতে
[ডেভ-নথি লেখার নির্দেশিকা](docs/guides/dev-docs-writing.en.md) দেখুন।
API উন্মুক্ত করে কর্মক্ষেত্রের মেটাডেটা (`/api/workspace`), স্কিল-তালিকা
(`/api/skills`), কোম্পানি-নথি পোর্টাল (`/api/portal`), এবং ফাইল-বদলের ঘটনা
পাঠানো WebSocket (`/api/ws`)। এই API-এর সুবাদে ড্যাশবোর্ড ছাড়া অন্য প্রোগ্রামও
কর্মক্ষেত্রে পৌঁছাতে পারে।

### স্কিল ব্যবস্থা

পুনরাবৃত্ত কাজগুলো পুনর্ব্যবহারযোগ্য স্কিলে গুছিয়ে রাখা হয়। প্রতিটি স্কিল ঠিক
একটি `SKILL.md` দিয়ে সংজ্ঞায়িত, আর API সার্ভার তালিকা বানাতে `skills/` স্ক্যান
করে। একটিমাত্র স্কিল বিন্যাস ভাঙলেই পুরো তালিকা ভুল তোলে (fail-closed): ভাঙা
স্কিল চুপচাপ বাদ দিয়ে বাকিটা পরিবেশনের বদলে অপারেটরকে তখনই ঠিক করতে বাধ্য করা
হয়। ভুল করে অসম্পূর্ণ তালিকা না পাঠানোর সচেতন সিদ্ধান্ত এটি।

### আজ স্কিল-বৃক্ষে যা আছে

স্কিল চার দলে ভাগ। কোনো সেশনে কী আছে জানতে প্রতিটি `SKILL.md` আবার না পড়তে হয়,
সেজন্য `.agents/context/skills-index.yaml` প্রতি স্কিলে এক লাইন রাখে—এটি কী করে,
কখন ধরতে হবে। নিচের তালিকা সেই সূচির সূচিপত্র।

**নথি ও বাইরের কাজ** — যা মানুষ পড়বে।
`doc-coauthoring` (স্পেসিফিকেশন ও ডিজাইন-নথি), `proposal-writing`, `read-doc`,
`translate-doc`, `press-release`, `weekly-report`, `document-generation`
(ব্র্যান্ডেড PDF ও ডিজিটাল স্বাক্ষর), `copyright-reg` (কপিরাইট নিবন্ধন),
`patent-draft` ও `patent-pipeline` (পেটেন্ট বিবরণ), `youtube-upload` (ভিডিও ও
সাবটাইটেল)।

**কর্মক্ষেত্র চালানো** — যে হাত রেপো ছোঁয়।
`project-create`, `project-migration`, `merge-worktree`, `migrate-ctx`,
`session-resume`, `sync-upstream` (আপস্ট্রিম সমন্বয়), `manage-skills`, এবং
এনক্রিপ্ট করা গোপন-সিন্দুকের জন্য `secret-vault`।

**যাচাই-ফটক** — যেখানে দাবির বদলে প্রমাণ চাওয়া হয়।
`verify-implementation`, `verify-contract-conformance`, `verify-request-contract`,
`verify-product-preservation`, `verify-benchmark-contract`, `verify-review-gate`,
`verify-build` (আসলেই বিল্ড হয় কি), `verify-conflict-markers` (সংঘাত-চিহ্ন
রয়ে গেছে কি), `verify-i18n` ও `verify-hardcoded-strings` (স্ট্রিং ঠিক জায়গায়
আছে কি), `webapp-testing`, এবং প্রতিকূল পর্যালোচনার জন্য `review-pass`।

**পরিচালনা ও পরীক্ষা** — বাইরে যাওয়া বা মডেল-ছোঁয়া কাজ।
Discord গেটওয়ের জন্য `manage-discord-sessions`, `channel-management`,
`service-management` (আপটাইম, খরচ, ঘটনা), `web-monitoring`, `email`, `sms`,
`upstream-pr-review` (OSS রক্ষণাবেক্ষকের কাছে যাওয়া সবকিছুর আগে ছাঁকনি),
`payroll`, এবং চরিত্র-LoRA প্রশিক্ষণের জন্য `finetune-persona`।

`.agents/skills/SKILL_TEMPLATE.md` থেকে নতুন স্কিল শুরু করুন, আর তৈরি হলেই সূচিতে
তার লাইন যোগ করুন। সূচি বৃক্ষ থেকে সরে গেলে পরের সেশন আগে থাকা স্কিল আবার গড়ে।

### নিয়ম ও ন্যূনতম শাসন

একা ব্যবহারের কর্মক্ষেত্রেও কিছু ন্যূনতম নিয়ম দরকার, যেই AI ও অটোমেশন তাতে
হাত দেয়। Naia ADK `read`, `write`, `execute` ও `publish`-কে আলাদা বিষয় হিসেবে
ভাগ করে, আর প্রতিটি নথিতে প্রকাশ-স্তর লাগায়। ফেরানো-কঠিন কাজ — প্রোডাকশন বদল,
গোপন-পরিচালনা, প্রকাশ্য দাবি — সাধারণ স্থানীয় সম্পাদনা থেকে আলাদা করে অনুমোদন-
ফটকে পাঠানো হয়।

প্রকাশের চার স্তর। `public` পাবলিক সাইট বা ওপেন-সোর্স রেপোতে যেমন আছে তেমন
নিরাপদ; `controlled` পর্যালোচনার পর বাইরে ভাগ করা যায়; `internal` কর্মক্ষেত্রের
ভেতরে থাকে; `confidential` চুক্তি, পরিচয়-তথ্য ও ব্যক্তিগত ডেটার মতো সংবেদনশীল
বিষয় ঢাকে। পরিচয়-তথ্য সাধারণত git-এর বাইরে থাকে, তবু স্তর হিসেবে
`confidential`।

> **সেশন-চুক্তি ফটক চিহ্নহীন checkout-এ সক্রিয়।** আবদ্ধ-নয় এমন সেশন নীতি-অনুমত
> রুটিন স্থানীয় কাজ করতে পারে, যেমন পরিদর্শন, `npm test`, বিল্ড, `mkdir`, এবং
> সাধারণ অ-ধ্বংসাত্মক Git stage/commit। শাসন ও হোস্ট-নীতি ফাইল, ভাগ করা
> প্রবেশ-বিন্দু, সেশন-চুক্তি ও রেজিস্ট্রি-কর্তৃত্ব, মোছা, ধ্বংসাত্মক বা দূরবর্তী
> কমান্ড, বাইরের প্রভাব, ও প্রোডাকশন বদলে এখনও চুক্তি লাগে। এটি রেপো-হুকের শাসন-
> পরীক্ষা; এটি অপারেটিং-সিস্টেম স্যান্ডবক্স নয় এবং হুকের বাইরে চালানো কমান্ডের
> নিশ্চয়তা দেয় না। নীতির জন্য `.agents/context/agents-rules.json` ও
> `.agents/context/harness.yaml` দেখুন। প্রকল্প-মূল বা কোনো পূর্বপুরুষে
> `.codex/no-harness`, `.claude/no-harness` বা `.pi/no-harness` চিহ্ন বংশধর
> checkout-এ উত্তরাধিকারসূত্রে আসে। এই প্রার্থী সেশন-চুক্তি হুককে Codex ও Claude-
> এর সাথে জোড়ে; এটি Pi সেশন-চুক্তি অ্যাডাপ্টার দাবি করে না।

### গোপন জিনিস কোথায় থাকে

API কী ও সার্টিফিকেট git-এ commit করা যায় না। কিন্তু প্রতিটি ল্যাপটপে রাখার
মানে—মেশিন বদলালেই হারিয়ে যায়, আর কে কী ধরে কেউ বলতে পারে না। Naia ADK এই
জট **ঠিক একটি ফাইল** commit করে খোলে: গোপন জিনিসের ফোল্ডার, আর্কাইভ ও
এনক্রিপ্ট করা। খোলা বিষয়বস্তু git কখনোই দেখে না।

বাস্তবে `key/` ফোল্ডার tar করে
[age](https://github.com/FiloSottile/age) দিয়ে একক `key.age`-তে এনক্রিপ্ট করা
হয়। `key/` আছে `.gitignore`-এ, তাই ভুলে commit হতে পারে না। commit-এ যাওয়া
একমাত্র জিনিস `key.age`।

পাসফ্রেজ মানুষ টাইপ করে। AI তা পায়ও না, কারো হয়ে টাইপও করে না। তাই সিন্দুক
খোলা ও সিল করা হয় ব্যবহারকারীর নিজের টার্মিনালে, আর পরীক্ষা ও ব্যাকআপ—যাতে
পাসফ্রেজ লাগে না—অর্পণ করা যায়। স্কিলের ভেতরে আদেশ-দর-আদেশ এই সীমা টানা হয়।

```bash
bash .agents/skills/secret-vault/scripts/vault.sh init     # create a vault in a new repo
bash .agents/skills/secret-vault/scripts/vault.sh unlock   # open it (passphrase)
bash .agents/skills/secret-vault/scripts/vault.sh lock     # seal it again (passphrase)
bash .agents/skills/secret-vault/scripts/vault.sh status   # is the backup current?
bash .agents/skills/secret-vault/scripts/vault.sh sync     # commit key.age and push
```

`status` আছে, কারণ ভুলের আকার নির্দিষ্ট। কী যোগ করে সিল করতে ভুলে যান, বা সিল
করে push করতে ভুলে যান, বা অস্থায়ী ফাইল পড়ে থাকে। `status` তিনটিই একসাথে খোঁজে।
কেউ কী-এর ব্যাকআপ আছে কি জিজ্ঞেস করলে স্মৃতি থেকে নয়, এই কমান্ডে উত্তর দিন।

`lock` নতুন সাইফারটেক্সট লেখে, **যাচাই করতে আবার ডিক্রিপ্ট করে**, তবেই পুরনো
ফাইল বদলায়—তাই আধা-সিল কখনো ভাঙা সিন্দুক রেখে যায় না।

এই ধরনের প্রমিত ভোক্তা `data-private`-এর মতো প্রাইভেট রেপো, তবে `key.age` ও
git-উপেক্ষিত `key/`-সহ যেকোনো রেপো এটি ব্যবহার করতে পারে। যেকোনো দিকের নাম
বদলাতে `VAULT` ও `PLAIN_DIR` ওভাররাইড করুন।

### LLM অ্যাডাপ্টার (naia-anyllm)

যে সুবিধাগুলোর LLM-এ পৌঁছানো দরকার, সেজন্য `naia-anyllm` অ্যাডাপ্টার ভেতরে
আছে। এটি [any-llm](https://github.com/nextain/any-llm) গেটওয়ে দিয়ে, বা সরাসরি
OpenAI, Anthropic ও Google-এর মতো প্রদানকারীর সাথে যুক্ত হয়। ডিফল্ট Naia
অ্যাকাউন্ট: [naia.nextain.io](https://naia.nextain.io)-তে ইস্যু করা কী `NAIA_KEY`
পরিবেশ-চলে রাখুন, আর সাথে সাথে অ্যাকাউন্ট-ক্রেডিট ব্যবহার করতে পারবেন। কী ছাড়া
এটি যেকোনো অর্থপ্রদান-কলের আগেই ভুল তোলে। প্রদানকারী বা মডেল বদলাতে
[`.agents/context/llm-config.yaml.example`](.agents/context/llm-config.yaml.example)
অনুলিপি করুন, আর API কী পরিবেশ-চল বা OS কীস্টোরে রাখুন, কনফিগ-ফাইলে কখনো নয়।
`naia-settings/llm.json` শুধু `apiKeyRef: "NAIA_KEY"` লেখে, কী-এর মান কখনো নয়।
ব্যক্তিগত ফোর্কে দীর্ঘমেয়াদি ব্যাকআপ দরকার হলে `data-private/key/`-তে age-
এনক্রিপ্ট করা সিন্দুক ব্যবহার করুন ([`.env.example`](.env.example) দেখুন)।

সমর্থিত মডেল ও বর্তমান দাম তালিকাভুক্ত করতে, এবং লম্বা PDF অনুবাদে, `translate-doc`
স্কিল ব্যবহার করুন। মডেল ও দাম-খোঁজ কী ছাড়াই চলে; অনুবাদ প্রথমে আনুমানিক খরচ
দেখায় এবং যেখানে থেমেছিল সেখান থেকে চালিয়ে যেতে পারে।

## কেন এভাবে বানানো

### বিন্যাসই চুক্তি

Naia ADK-এর হৃদয় কোনো বিশেষ টুল নয়, বরং একটি **বিন্যাস**। ডিরেক্টরি-বিন্যাস
(`.agents/`, `.users/`, `skills/`, `data-*/`) ও ফাইল-স্কিমা (`agents-rules.json`,
`SKILL.md`) একটি স্থির চুক্তি, আর যে টুল সেই চুক্তি পড়তে পারে সে-ই একই
কর্মক্ষেত্র ব্যবহার করতে পারে। Claude Code, Codex, opencode, naia-agent, agy ও
muse একে অন্যের কোড না ঢুকিয়ে একই কর্মক্ষেত্র পড়ে। তাই টুল বদলাতে বা কয়েকটি
মেশাতে পারেন, আর কর্মক্ষেত্র চলতে থাকে।

নিয়ম-প্রয়োগও টুল-নিরপেক্ষ। হোস্ট-নিরপেক্ষ কোর (`.agents/hooks/core/`) ও নীতি
(`.agents/hooks/policies/`) একই নিয়মে Claude Code হুক ও pi এক্সটেনশন দুটোই
চালায়।

### দলে বাড়ার আগে ব্যক্তিগত ভিত্তি

Naia ADK কঠোরভাবে একক-ব্যবহারকারী, ব্যক্তিগত ব্যবহারের জন্য। কোম্পানি-কাঠামো,
টেনান্ট-নিয়ম ও অর্পিত-অনুমোদন শৃঙ্খল ওপরের স্তরের। এটি দেয় প্রসঙ্গ-শৃঙ্খলা
লেখার একটিমাত্র জায়গা—কর্মক্ষেত্র দল বা কোম্পানি মাপে বাড়ার আগে।

দলগত সহযোগিতা ও ভাগ করা জ্ঞানের জন্য
[Naia Business ADK](https://nextain.io/adk) দিয়ে দেখানো ঐচ্ছিক সাংগঠনিক বংশ
বেছে নিতে পারেন। এটি সম্পদ, প্রক্রিয়া ও অনুমতি-শাসন, দল-মালিকানা ও অর্পিত
অনুমোদন যোগ করে।

### ফোর্ক-বংশ

Naia ADK আপনার নিজের কর্মক্ষেত্রে ফোর্ক হওয়ার জন্য। ব্যক্তিরা সরাসরি `naia-adk`
ফোর্ক করতে পারেন। সংস্থা কোম্পানি ও সদস্য-কর্মক্ষেত্রের জন্য `naia-business-adk`-
এর মতো আলাদা সাংগঠনিক বংশ বেছে নিতে পারে। কোনো ব্যবহারকারীর জন্য একটিমাত্র
স্থির শৃঙ্খল আবশ্যক নয়।

```
naia-adk                  ← public personal base (Apache 2.0)
  └── {user}-adk          ← direct personal fork

naia-business-adk         ← optional organization lineage
  └── {org}-adk            ← org fork: company data + business submodules
        └── {member}-adk    ← member workspace derived from the organization
```

Nextain-এর অভ্যন্তরীণ বংশ আলাদা পরিচালন-উদাহরণ। সাধারণ ব্যবহারকারী সরাসরি
ব্যক্তিগত ফোর্ক রেখে অ্যাকাউন্ট-নামে `{user}-adk` নাম দিতে পারেন।

প্রকল্প/দল-ভিত্তি দরকার হলে আলাদা ভিত্তি হিসেবে
[naia-pj-adk](https://github.com/nextain/naia-pj-adk) বেছে নিতে পারেন। PJ
বহু-প্রকল্প প্রসঙ্গ-সরণ, কল-খরচ ও Discord-পরিচালন সীমার অ্যাডাপ্টার-ভিত্তি।
ব্যক্তিগত-ফোর্ক সাজানো ও দল-ভূমিকা/কাজ-ঘণ্টা নিয়ম আলাদা বিষয়। সেই কাজ
গোছাতে ও খুঁজতে সাহায্য করা এই কাঠামোর নকশা-লক্ষ্য, খরচ-বাঁচানো বা কম-সময়ের
মাপা নিশ্চয়তা নয়। PJ ভিত্তি ব্যক্তিগত ফোর্কের মূল-রেপো নয়। সাংগঠনিক
সহযোগিতার জন্য `naia-business-adk` ঐচ্ছিক।

### রানটাইম প্যাকেজ (packages/, মোট ১২)

তিনটি আসলে চলা প্রোগ্রাম; বাকিগুলো পাতলা প্যাকেজ, বিন্যাস ও বিবরণ সংজ্ঞায়িত
করে।

- `core` — কর্মক্ষেত্র ও স্কিল পার্স করা ইঞ্জিন।
- `server` — Fastify REST/WebSocket API।
- `dashboard` — Next.js ড্যাশবোর্ড UI।
- `skill-spec` — টুল-নিরপেক্ষ স্কিল-বিন্যাস চুক্তি (`SkillDescriptor`,
  `SkillLoader`)।
- `skills-builtin` — সাধারণ স্কিল-তালিকা।
- `openclaw-compat` — OpenClaw স্কিল naia-বিন্যাসে আনার টুল।
- `persona` — সিস্টেম-প্রম্প্ট রীতি-বিবরণ।
- `process` — কর্মপ্রবাহ-ধরন বিবরণ (পর্যালোচনা → সিদ্ধান্ত → সম্পাদন,
  ইস্যু-চালিত উন্নয়ন ইত্যাদি)।
- `naia-anyllm` — any-llm গেটওয়ে / সরাসরি-প্রদানকারী LLM অ্যাডাপ্টার।
- `artifacts-spec` — অনুমতি (RBAC) ও উন্নয়ন-জীবনচক্র (SDLC) শিল্পকর্মের প্রমিত
  স্কিমা। 15 ধরনের শিল্পকর্ম JSON Schema-তে সংজ্ঞায়িত করে, আর প্রতিটির জন্য
  বলে ইনস্ট্যান্স git-ট্র্যাকড না সেশন-সীমিত।
- `ax-messenger` — Matrix বার্তাবাহক রিলে/প্রশাসন প্যাকেজ (AI রিলে, লেজার ও
  `matrix-js-sdk`-এর ওপর প্রদানকারী)।
- `benchmark-contract` — `naia-adk` ও `naia-agent` ভাগ করা স্থায়ী বেঞ্চমার্ক ও
  শাসন-প্রমাণ চুক্তি।

### কর্মী-স্তর ও পর্যালোচক-ওভাররাইড

ভূমিকা ও মডেল আলাদা কনফিগার করা হয় — কোনো মডেল-সংস্করণ আর্কিটেকচারে পোঁতা নয়।

- `config/tier-profile.example.json` (`tier-profile/v1`) মডেল-নিরপেক্ষ 4-স্তর
  কর্মী-প্রোফাইল। স্তর *ভূমিকা* বর্ণনা করে (হালকা পরীক্ষা, ডিজাইন ও বাস্তবায়ন,
  ভূমিকা-সেশন, স্বাধীন পর্যালোচনা); প্রতি স্তরের প্রার্থীরা CLI ও মডেল আলাদা
  বাঁধে, তাই মডেল বদলালে ভূমিকা-কাঠামো কখনো বদলায় না।
- অনুমোদন-ফটক পর্যালোচক-ওভাররাইড ইনস্ট্যান্সের `.claude/deploy/config.json`-এ
  `review_models` হিসেবে থাকে (পর্যালোচক id → সঠিক মডেল, ন্যূনতম প্রচেষ্টা,
  রানার)। `CFG-` অনুমোদনের পরই প্রযোজ্য; অনুমোদিত কনফিগ ছাড়া কোড-ডিফল্ট
  প্রযোজ্য। রানারে `agy`, `muse`, `codex` ও `claude` আছে।
  [অনুমোদন-পরিকল্পনা ফটক নির্দেশিকা](docs/guides/approval-plan-gate.en.md) দেখুন।
- `naia-settings/review.json` আন্তঃরেপো পর্যালোচনা-প্যানেল ও মডেল-স্তর নীতি রাখে,
  যা `review-pass` স্কিল ও `naia-agent` ব্যবহার করে।

### দুটি স্কিল-বৃক্ষ

স্কিল দুই জায়গায় থাকে, দুই পক্ষ ব্যবহার করে।

- `.agents/skills/` — AI-সহায়তা ও কর্মপ্রবাহ স্কিল। Claude Code `.claude/skills/`
  সিমলিংকে ব্যবহার করে। পর্যালোচনা (`review-pass`), যাচাই
  (`verify-implementation`), ওয়ার্কট্রি-মার্জ (`merge-worktree`), নথি-নিষ্কাশন
  (`read-doc`), পেটেন্ট/কপিরাইট/বেতনের মতো ব্যবসা-স্কিল, ও `finetune-persona`,
  `secret-vault`, `youtube-upload`-এর মতো অন্যান্য আছে।
- `skills/` — পরিচালন/রানটাইম স্কিল। API সার্ভার `skills/**/SKILL.md` স্ক্যান
  করে ড্যাশবোর্ডে পরিবেশন করে। এতে ইমেল/SMS/বিজ্ঞপ্তি পাঠানো, চ্যানেল পরিচালনা,
  সেবা ও ওয়েব-পর্যবেক্ষণ, নথি-উৎপাদন আছে; `skills/business/`-তে `press-release`-
  এর মতো সাংগঠনিক স্কিল আছে।

সবচেয়ে নির্ভুল তালিকা ড্যাশবোর্ডের স্কিল-তালিকা। পাঠ-টেবিল
[স্কিল-সূচিতে](.agents/context/skills-index.yaml)।

## শুরু করা

### ব্যক্তিগত

1. নিজের অ্যাকাউন্টে `naia-adk` ফোর্ক করুন (পারলে প্রাইভেট)।
2. ক্লোন করুন: `git clone https://github.com/YOUR-USER/your-adk.git && cd your-adk`
3. আপস্ট্রিম যোগ করুন: `git remote add upstream https://github.com/nextain/naia-adk.git`
4. ডেটা ডিরেক্টরি বানান: `mkdir -p data-private projects`
5. প্রকল্প যোগ করুন, `.agents/` সাজান, কাজ শুরু করুন।
6. Naia অ্যাকাউন্ট-সম্পদ ব্যবহার করলে `NAIA_KEY` পরিবেশ-চল হিসেবে সেট করুন।
7. নিয়মিত সমন্বয় করুন: `git fetch upstream && git merge upstream/main`

### কোম্পানি

1. `naia-business-adk` অ্যাক্সেসের জন্য [যোগাযোগ করুন](https://nextain.io/contact)।
2. সংস্থা-অ্যাকাউন্টে `naia-business-adk` প্রাইভেট ফোর্ক করে ক্লোন করুন।
3. আপস্ট্রিম যোগ করুন: `git remote add upstream https://github.com/nextain/naia-business-adk.git`
4. কোম্পানি-ডেটা ও প্রকল্প-সাবমডিউল ভরুন: `mkdir -p data-company projects`,
   `git submodule add <repo> projects/<name>`
5. প্রতিটি সদস্য সংস্থা-ADK আবার ব্যক্তিগত কর্মক্ষেত্র হিসেবে ফোর্ক করে।

### Naia Shell সংযোগ (ঐচ্ছিক)

[Naia Shell](https://github.com/nextain/naia-shell) ডেস্কটপ ও ওয়েব-অ্যাপ

তে পরিবেশিত হয়।
