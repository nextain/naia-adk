# Naia ADK

**هيكل مساحة عمل مُرتَّب مسبقًا ليعمل فيه وكلاء الترميز بالذكاء الاصطناعي.**

عند استخدام أدوات الترميز بالذكاء الاصطناعي مثل Claude Code أو Codex، يحفظ كل
أداة ملفات القواعد في مكان مختلف، وتُجاب أسئلة مثل «هل يمكن نشر هذا المستند؟»
أو «أين تذهب المهارات؟» بارتجال. يضع Naia ADK هذا الهيكل مسبقًا. فكما تُجهِّز
بيئة التطوير على حاسوب محمول جديد، يسلِّم لوكيل الذكاء الاصطناعي مكتبًا مرتبًا
ليبدأ منه. كما يوفّر لوحة متابعة تُظهر حالة مساحة العمل بنظرة واحدة.

## يعمل خلال ٥ دقائق

تحتاج إلى **Node 22+‎** و**pnpm 9+‎**.

```bash
pnpm install    # install workspace dependencies
pnpm dev        # run the API server (:3141) and dashboard (:3142) together
```

افتح `http://localhost:3142` في المتصفح لرؤية اللوحة. ثلاثة أشياء تظهر فورًا:

- **Workspace** — المشاريع والوحدات الفرعية، وشجرة الملفات، ومستوى الإفصاح لكل
  عنصر.
- **Skills catalog** — قائمة المهارات المسجلة في مساحة العمل هذه ومحتواها.
- **Settings / monitoring** — إعدادات الخادم، وحالة العملاء، وأدلة البيانات.

تُحوِّل اللوحة إلى خادم API على المنفذ 3141 طلبات `/api/portal` الخاصة بعرض
المستندات فقط. لتشغيل أحدهما فقط استخدم `pnpm dev:server` (→ 3141) أو
`pnpm dev:dashboard` (→ 3142). يشغِّل سكربتا الإطلاق `./start.sh` (لينكس/ماك) و
`start.bat` (ويندوز) الأمر `pnpm dev` معًا. يقبل خادم CLI الخيارات `--port` و
`--host` و`--root`؛ فمثلًا وجِّهه إلى مساحة عمل أخرى بالأمر
`pnpm serve -- --root /path/to/workspace`.

## ما الذي في الداخل

### هيكل مساحة العمل

يمنح وكيل الذكاء الاصطناعي مجموعة أدلة ذات أماكن ثابتة لكل شيء، ليبدأ العمل
فورًا. يعيش السياق الموجَّه للذكاء الاصطناعي في `.agents/` (بالإنجليزية،
JSON/YAML). وتعيش الأدلة المقروءة للبشر في `.users/context/` (بالكورية) و
`.users/context/en/` (بالإنجليزية). هذه المرآة جزئية وليست نسخة كاملة — فهي تحمل
فقط المستندات التي يحتاج الإنسان لقراءتها (فالمهارات معيارية مثلًا تحت
`.agents/skills/`، ولا يُعكس منها إلى `.users/skills/` إلا بعضها). للمهارات
والبيانات والمشاريع أماكن مخصصة، فتبدو مساحة العمل واحدة أيًّا كانت الأداة التي
تفتحها.

### اللوحة وواجهة API

تدير لوحة Next.js مساحة العمل بصريًا، ويدعمها خادم API من نوع Fastify. يعرض
تبويبا **Docs** (`/docs`) و**Work** في التنقل العلوي مستندات الشركة المشتركة
ولوحة التعاون في مكان واحد، ويُعِدّ الأمر
`pnpm adk:setup -- --company <repo-url>` مستودعات مستندات الشركة والمشاريع في
خطوة واحدة. ولتفاصيل الإعداد والاستخدام راجع
[دليل الانضمام](docs/guides/onboarding.en.md)
([한국어](docs/guides/onboarding.ko.md)).
وراجع [دليل كتابة وثائق التطوير](docs/guides/dev-docs-writing.en.md)
لتوثيق البنية والعقود وأدلة التنفيذ.
تكشف الواجهة بيانات مساحة العمل الوصفية (`/api/workspace`)، وفهرس المهارات
(`/api/skills`)، وبوابة مستندات الشركة (`/api/portal`)، ومقبس WebSocket يبث أحداث
تغيُّر الملفات (`/api/ws`). وبفضل هذه الواجهة تصل إلى مساحة العمل برامج أخرى غير
اللوحة.

### نظام المهارات

تُجمَّع المهام المتكررة في مهارات قابلة لإعادة الاستخدام. تُعرَّف كل مهارة بملف
واحد `SKILL.md`، ويمسح خادم API المجلد `skills/‎` لبناء الفهرس. إذا خالفت مهارة
واحدة التنسيق سقط الفهرس كله بخطأ (إغلاق صارم): فبدل إسقاط المهارة المعطوبة
بصمت وخدمة الباقي، يُلزَم المشغِّل بإصلاحها فورًا. وهو خيار مقصود لمنع شحن فهرس
ناقص بالخطأ.

### ما في شجرة المهارات اليوم

تنقسم المهارات إلى أربع مجموعات. وحتى لا تُعيد الجلسة قراءة كل `SKILL.md`
لمعرفة الموجود، يحمل الملف `.agents/context/skills-index.yaml` سطرًا لكل مهارة
يقول ماذا تفعل ومتى تُستخدم. والقائمة أدناه فهرس ذلك الفهرس.

**المستندات والعمل الخارجي** — ما سيقرؤه الإنسان.
`doc-coauthoring` (المواصفات ومستندات التصميم)، و`proposal-writing`، و`read-doc`،
و`translate-doc`، و`press-release`، و`weekly-report`، و`document-generation`
(ملفات PDF بالهوية وأختام رقمية)، و`copyright-reg` (تسجيلات حقوق النشر)،
و`patent-draft` و`patent-pipeline` (براءات الاختراع)، و`youtube-upload`
(الفيديو والترجمة).

**تشغيل مساحة العمل** — الأيادي التي تلمس المستودع نفسه.
`project-create`، و`project-migration`، و`merge-worktree`، و`migrate-ctx`،
و`session-resume`، و`sync-upstream` (المزامنة مع الأصل)، و`manage-skills`،
و`secret-vault` لخزانة الأسرار المشفَّرة.

**بوابات التحقق** — الأماكن التي تطلب الأدلة لا الادعاءات.
`verify-implementation`، و`verify-contract-conformance`، و`verify-request-contract`،
و`verify-product-preservation`، و`verify-benchmark-contract`، و`verify-review-gate`،
و`verify-build` (هل يُبنى فعلًا)، و`verify-conflict-markers` (هل بقيت علامات
تعارض)، و`verify-i18n` و`verify-hardcoded-strings` (هل السلاسل في أماكنها)،
و`webapp-testing`، و`review-pass` للمراجعة العدائية.

**العمليات والتجارب** — العمل الخارج أو الملامس للنماذج.
`manage-discord-sessions` لبوابة Discord، و`channel-management`،
و`service-management` (الإتاحة والتكلفة والحوادث)، و`web-monitoring`، و`email`،
و`sms`، و`upstream-pr-review` (بوابة قبل كل ما يذهب لمشرفي المصادر المفتوحة)،
و`payroll`، و`finetune-persona` لتدريب LoRA للشخصيات.

ابدأ مهارة جديدة من `.agents/skills/SKILL_TEMPLATE.md`، وأضف سطرها إلى الفهرس
عند وجودها. وعندما ينحرف الفهرس عن الشجرة تُعيد الجلسة التالية بناء مهارة كانت
عندها.

### القواعد والحوكمة الدنيا

حتى مساحة العمل الفردية تحتاج قواعد دنيا ما إن يلمسها الذكاء الاصطناعي
والأتمتة. يفصل Naia ADK بين `read` و`write` و`execute` و`publish` كشواغل مستقلة،
ويعلِّق على كل مستند مستوى إفصاح. تُفصَل الإجراءات صعبة التراجع — تغييرات
الإنتاج، ومعالجة الأسرار، والادعاءات العامة — عن التعديلات المحلية العادية
وتُوجَّه عبر بوابات الموافقة.

للإفصاح أربعة مستويات. `public` آمن للنشر كما هو على موقع عام أو مستودع مفتوح؛
و`controlled` يُشارَك خارجيًا بعد المراجعة؛ و`internal` يبقى داخل مساحة العمل؛
و`confidential` يغطي المواد الحساسة كالعقود وبيانات الاعتماد والبيانات الشخصية.
تعيش بيانات الاعتماد عادة خارج git، لكنها تبقى `confidential` بالمستوى.

> **بوابة عقد الجلسة نشطة في نسخة عمل بلا علامات.** يجوز لجلسة غير مرتبطة
> القيام بعمل محلي روتيني تسمح به السياسة مثل الفحص، و`npm test`، والبناء، و
> `mkdir`، وعمليات Git stage/commit العادية غير المدمِّرة. أما ملفات الحوكمة
> وسياسة المضيف، ونقاط الدخول المشتركة، وعقود الجلسات وسلطة السجل، والحذف،
> والأوامر المدمِّرة أو البعيدة، والآثار الخارجية، وتغييرات الإنتاج فما تزال
> تتطلب عقدًا. هذا فحص حوكمة لخطافات المستودع؛ وليس صندوق رمل لنظام التشغيل ولا
> يضمن الأوامر المطلَقة خارج الخطافات. راجع
> `.agents/context/agents-rules.json` و`.agents/context/harness.yaml` للسياسة.
> تورَّث علامة `.codex/no-harness` أو `.claude/no-harness` أو `.pi/no-harness` في
> جذر المشروع أو أي سلف لنسخ العمل المتفرعة. يربط هذا المرشَّح خطاف عقد الجلسة
> بـ Codex وClaude؛ ولا يدَّعي محوِّل Pi لعقد الجلسة.

### أين تعيش الأسرار

لا يمكن إيداع مفاتيح API والشهادات في git. لكن الاحتفاظ بها على كل حاسوب يعني
اختفاءها عند تبدُّل الجهاز، ولا يستطيع أحد قول من يحمل ماذا. يحسم Naia ADK هذه
العقدة بإيداع **ملف واحد فقط**: مجلد الأسرار مؤرشفًا ومشفَّرًا. والمحتوى المفكوك
لا يراه git أبدًا.

عمليًا يُحزَم المجلد `key/‎` بتار ويُشفَّر باستخدام
[age](https://github.com/FiloSottile/age) في ملف واحد `key.age`. و`key/‎` في
`.gitignore` فلا يمكن إيداعه بالخطأ. والشيء الوحيد الذي يصل إلى أي إيداع هو
`key.age`.

يكتب الإنسان عبارة المرور. فلا يستلمها الذكاء الاصطناعي ولا يكتبها نيابة عن أحد.
لذا يجري فتح الخزانة وإغلاقها في طرفية المستخدم نفسه، بينما يمكن تفويض الفحص
والنسخ الاحتياطي — اللذين لا يحتاجان العبارة. وتُرسَم هذه الحدود أمرًا بأمر داخل
المهارة.

```bash
bash .agents/skills/secret-vault/scripts/vault.sh init     # create a vault in a new repo
bash .agents/skills/secret-vault/scripts/vault.sh unlock   # open it (passphrase)
bash .agents/skills/secret-vault/scripts/vault.sh lock     # seal it again (passphrase)
bash .agents/skills/secret-vault/scripts/vault.sh status   # is the backup current?
bash .agents/skills/secret-vault/scripts/vault.sh sync     # commit key.age and push
```

وُجد `status` لأن الأخطاء ذات شكل ثابت. تضيف مفتاحًا وتنسى الختم، أو تختم وتنسى
الدفع، أو يُترَك ملف مؤقت. يبحث `status` عن الثلاثة معًا. وعندما يُسأَل هل
المفاتيح منسوخة أجب بهذا الأمر لا من الذاكرة.

يكتب `lock` النص المشفَّر الجديد، **ثم يفكّه مجددًا للتحقق**، وعندها فقط يستبدل
الملف القديم — فلا يترك الختم الناقص خزانة معطوبة أبدًا.

المستهلك المعتاد لهذا النمط مستودع خاص مثل `data-private`، لكن أي مستودع فيه
`key.age` ومجلد `key/‎` متجاهَل يصلح. وأعِد تعريف `VAULT` و`PLAIN_DIR` لإعادة
تسمية أي من الجهتين.

### محوِّل LLM ‏(naia-anyllm)

للمزايا التي تحتاج الوصول إلى LLM يأتي المحوِّل `naia-anyllm` مدمجًا. يتصل عبر
بوابة [any-llm](https://github.com/nextain/any-llm) أو مباشرة بمزودين مثل OpenAI
وAnthropic وGoogle. والافتراضي حساب Naia: ضع مفتاحًا صادرًا من
[naia.nextain.io](https://naia.nextain.io) في متغير البيئة `NAIA_KEY` وستستخدم
أرصدة حسابك فورًا. وبلا مفتاح يُطلِق خطأ قبل أي استدعاء مدفوع. لتبديل المزود أو
النماذج انسخ
[`.agents/context/llm-config.yaml.example`](.agents/context/llm-config.yaml.example)،
واحفظ مفاتيح API في متغيرات البيئة أو مخزن مفاتيح النظام، لا في ملف الإعداد.
يسجِّل `naia-settings/llm.json` فقط `apiKeyRef: "NAIA_KEY"‎` لا قيمة المفتاح. وإذا
احتاج فرع شخصي لنسخ طويل الأمد استخدم الخزانة المشفَّرة بـ age في
`data-private/key/‎` (راجع [`.env.example`](.env.example)).

لسرد النماذج المدعومة وأسعارها الحالية، ولترجمة ملفات PDF الطويلة، استخدم مهارة
`translate-doc`. تعمل استعلامات النماذج والأسعار بلا مفتاح؛ وتعرض الترجمة التكلفة
التقديرية أولًا ويمكنها الاستئناف من حيث توقفت.

## لماذا بُني هكذا

### التنسيق هو العقد

قلب Naia ADK ليس أداة بعينها بل **تنسيق**. فتخطيط الأدلة (`.agents/` و`.users/`
و`skills/` و`data-*/‎`) ومخططات الملفات (`agents-rules.json` و`SKILL.md`) اتفاق
ثابت، وأي أداة تقرؤه تستهلك مساحة العمل نفسها. يقرأ Claude Code وCodex وopencode
وnaia-agent وagy وmuse المساحة نفسها دون تضمين شيفرة بعضهم. فيمكنك تبديل الأدوات
أو المزج بينها وتبقى مساحة العمل عاملة.

وإنفاذ القواعد نفسه لا يعتمد على أداة. فالنواة المحايدة للمضيف
(`.agents/hooks/core/‎`) والسياسات (`.agents/hooks/policies/‎`) تقود خطافات
Claude Code وامتداد pi بالقواعد نفسها.

### قاعدة شخصية قبل النمو إلى فريق

Naia ADK أحادي المستخدم حصرًا للاستعمال الشخصي. فالمخططات التنظيمية للشركات
وقواعد المستأجرين وسلاسل الموافقة المفوَّضة تنتمي لطبقة أعلى. وما يمنحك إياه مكان
واحد لتدوين انضباط السياق قبل نمو مساحة العمل إلى مقياس الفريق أو الشركة.

للتعاون الجماعي والمعرفة المشتركة يمكنك اختيار النسب التنظيمي الاختياري الممثَّل
في [Naia Business ADK](https://nextain.io/adk). فهو يضيف حوكمة الأصول والعمليات
والأذونات وملكية الفريق والموافقات المفوَّضة.

### أنساب الفروع

صُمم Naia ADK ليُفرَّع إلى مساحة عملك الخاصة. يجوز للأفراد تفر يع `naia-adk`
مباشرة. ويجوز للمنظمة اختيار نسب تنظيمي منفصل مثل `naia-business-adk` لمساحات
الشركة والأعضاء. ولا تُشترَط سلسلة ثابتة واحدة لأي مستخدم.

```
naia-adk                  ← public personal base (Apache 2.0)
  └── {user}-adk          ← direct personal fork

naia-business-adk         ← optional organization lineage
  └── {org}-adk            ← org fork: company data + business submodules
        └── {member}-adk    ← member workspace derived from the organization
```

والنسب الداخلي لـ Nextain مثال تشغيلي منفصل. ويجوز للمستخدم العام الاحتفاظ بفرع
شخصي مباشر وتسميته `{user}-adk` باسم الحساب.

وإذا احتجت أساس مشروع/فريق يمكنك اختيار
[naia-pj-adk](https://github.com/nextain/naia-pj-adk) كأساس منفصل. فـ PJ أساس
محوِّل لانحراف السياق متعدد المشاريع وتكلفة الاستدعاءات وحدود تشغيل Discord.
وتخصيص الفرع الشخصي وقواعد أدوار الفريق وساعات العمل شواغل منفصلة. والمساعدة في
تنظيم ذلك العمل وتتبعه هدف تصميمي لهذا الهيكل، لا ضمان مقاس لتوفير التكلفة أو
تقصير المدة. وأساس PJ ليس المستودع الأب لفرع شخصي. و`naia-business-adk` — عندما
تحتاج تعاونًا تنظيميًا — اختياري.

## البنية

ينقسم المستودع إلى شيفرة التشغيل (`packages/‎`) والقواعد والسياق (`.agents/`
و`.users/‎`) والمهارات (`skills/‎` و`.agents/skills/‎`) وأدلة البيانات التي
يملؤها كل فرع.

| Directory | Purpose |
|-----------|---------|
| `.agents/` | سياق الذكاء الاصطناعي (بالإنجليزية، JSON/YAML) — المصدر الوحيد للحقيقة للقواعد |
| `.users/context/` | أدلة مقروءة للبشر (بالكورية، Markdown) |
| `.users/context/en/` | مرآة إنجليزية مقروءة (Markdown) |
| `.claude/` | إعداد Claude Code والخطافات وروابط المهارات |
| `skills/` | مهارات التشغيل (تخدمها API اللوحة) |
| `scripts/` | سكربتات مساعدة |
| `templates/` | قوالب المستندات |
| `docs/` | وثائق البنية ومواصفات التصميم |
| `packages/` | حزم التشغيل (مساحة pnpm) |
| `config/` | أمثلة ملفات العاملين وإعداد النشر |

### حزم التشغيل (packages/‎، ١٢ حزمة)

ثلاث منها برامج عاملة فعلًا؛ والباقي حزم نحيفة تحدِّد التنسيقات والمواصفات.

- `core` — المحرك الذي يحلِّل مساحة العمل والمهارات.
- `server` — واجهة Fastify من نوع REST/WebSocket.
- `dashboard` — واجهة اللوحة على Next.js.
- `skill-spec` — عقد تنسيق المهارات المستقل عن الأدوات (`SkillDescriptor` و
  `SkillLoader`).
- `skills-builtin` — فهرس المهارات العام.
- `openclaw-compat` — أداة تهاجر مهارات OpenClaw إلى تنسيق naia.
- `persona` — مواصفة اصطلاح موجِّه النظام.
- `process` — مواصفة أنماط سير العمل (مراجعة ← قرار ← تنفيذ، والتطوير الموجَّه
  بالقضايا، وهكذا).
- `naia-anyllm` — محوِّل LLM عبر بوابة any-llm / المزودين المباشرين.
- `artifacts-spec` — المخطط المعياري لمصنوعات الأذونات (RBAC) ودورة حياة التطوير
  (SDLC). يحدِّد ١٥ نوعًا من المصنوعات بصيغة JSON Schema، ويبيِّن لكل منها هل
  النُسخة متتبَّعة بـ git أم محصورة بالجلسة.
- `ax-messenger` — حزمة ترحيل/إدارة مراسلة Matrix (ترحيل الذكاء الاصطناعي والسجل
  والمزودون فوق `matrix-js-sdk`).
- `benchmark-contract` — عقود القياس وأدلة الحوكمة الدائمة المشتركة بين
  `naia-adk` و`naia-agent`.

### مستويات العاملين وتجاوزات المراجعين

تُعَدّ الأدوار والنماذج منفصلة — فلا تُخبَز أي نسخة نموذج في البنية.

- `config/tier-profile.example.json` (الإصدار `tier-profile/v1`) ملف عاملين من
  أربع مستويات مستقل عن النماذج. تصف المستويات *الأدوار* (فحوص خفيفة، وتصميم
  وتنفيذ، وجلسات أدوار، ومراجعة مستقلة)؛ ويربط مرشَّحو كل مستوى CLI والنموذج
  منفصلين، فلا يغيِّر تبديل النموذج بنية الأدوار أبدًا.
- تعيش تجاوزات مراجعي بوابات الموافقة في
  `.claude/deploy/config.json` الخاص بالنسخة بصيغة `review_models` (معرِّف
  المراجع ← النموذج الدقيق، والحد الأدنى للجهد، والمشغِّل). ولا تُطبَّق إلا بعد
  موافقة `CFG-‎`؛ وبلا إعداد معتمَد تسري افتراضات الشيفرة. ومن المشغِّلين `agy`
  و`muse` و`codex` و`claude`. راجع
  [دليل بوابة خطة الموافقة](docs/guides/approval-plan-gate.en.md).
- يحفظ `naia-settings/review.json` لوحة المراجعة عبر المستودعات وسياسة مستويات
  النماذج التي تستهلكها مهارة `review-pass` و`naia-agent`.

### أدلة البيانات (gitignored، تُملأ لكل فرع)

هذه الأربعة لا تُودَع أبدًا. فمن يفرِّع المستودع يملأ بياناته.

| Directory | Scope | Content |
|-----------|-------|---------|
| `data-company/` | Company | مستندات الشركة ومواردها المشتركة |
| `data-teams/` | Team | مستندات الفرق (الاستراتيجية والمحاسبة إلخ) |
| `data-private/` | Personal | بيانات شخصية وملفات env ومستندات خاصة |
| `projects/` | Personal | مستودعات المشاريع (وحدات فرعية) |

### شجرتا مهارات

تعيش المهارات في مكانين تستهلكهما جهتان مختلفتان.

- `.agents/skills/‎` — مهارات مساعدة الذكاء الاصطناعي وسير العمل. يستخدمها
  Claude Code عبر الرابط `.claude/skills/‎`. وتشمل المراجعة (`review-pass`)
  والتحقق (`verify-implementation`) ودمج شجرة العمل (`merge-worktree`) واستخراج
  المستندات (`read-doc`) ومهارات الأعمال كالبراءات وحقوق النشر والرواتب وغيرها
  مثل `finetune-persona` و`secret-vault` و`youtube-upload`.
- `skills/‎` — مهارات التشغيل. يمسح خادم API المسار `skills/**/SKILL.md` ويخدمها
  للوحة. وتشمل إرسال البريد والرسائل والتنبيهات وإدارة القنوات ومراقبة الخدمات
  والويب وتوليد المستندات؛ ويحمل `skills/business/‎` مهارات تنظيمية مثل
  `press-release`.

أدق قائمة هي فهرس المهارات في اللوحة. وجدول نصي في
[فهرس المهارات](.agents/context/skills-index.yaml).

## البدء

### شخصي

1. فرِّع `naia-adk` إلى حسابك (خاص إن أمكن).
2. استنسخه: `git clone https://github.com/YOUR-USER/your-adk.git && cd your-adk`
3. أضف الأصل: `git remote add upstream https://github.com/nextain/naia-adk.git`
4. أنشئ أدلة البيانات: `mkdir -p data-private projects`
5. أضف مشاريع واضبط `.agents/‎` وابدأ العمل.
6. إذا استخدمت موارد حساب Naia فعيِّن `NAIA_KEY` كمتغير بيئة.
7. زامِن دوريًا: `git fetch upstream && git merge upstream/main`

### للشركات

1. [تواصل معنا](https://nextain.io/contact) للوصول إلى `naia-business-adk`.
2. فرِّع `naia-business-adk` بخصوصية في حساب منظمتك ثم استنسخه.
3. أضف الأصل: `git remote add upstream https://github.com/nextain/naia-business-adk.git`
4. املأ بيانات الشركة والوحدات الفرعية: `mkdir -p data-company projects`،
   `git submodule add <repo> projects/<name>`
5. يفرِّع كل عضو ADK المنظمة مجددًا كمساحة شخصية.

### تكامل Naia Shell (اختياري)

إذا استخدمت تطبيق [Naia Shell](https://github.com/nextain/naia-shell) لسطح
المكتب والويب فوجِّه مسار مساحة العمل إلى مجلد ADK. تُخدَم المهارات والبيانات عبر
الواجهة.
