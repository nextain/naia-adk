# 장부가 일을 굴린다 — 설계

기준 커밋: d2a2693dc6f52213cfa94725a5c0dded48879102.
구현: `scripts/work-ledger-drive.mjs`, 시험: `scripts/work-ledger-drive.test.mjs`,
쓰는 법: [work-ledger-drive 안내](../guides/work-ledger-drive.md).

이 문서에서 3층·2층은 오케스트레이션 층위(L3 비서, L2 이슈 리더)를 뜻한다.

## 풀려는 문제

역할별 업무 장부는 기한이 지나면 3층을 깨우기만 했다. 일을 띄우는 것은 3층의
기억과 여력에 달려 있었고, 3층은 기한을 넘긴 항목을 `dropped` 로 닫고 새 기한의
새 항목으로 다시 올릴 수 있었다. 그 결과 장부는 밀린 일을 줄이지 못하고 기록만
늘렸다. 원인은 셋이다.

1. 항목에 "무엇을 어떻게 하라"가 없다. 제목과 기한뿐이라 장치가 대신 시작할 수 없다.
2. 기한 넘김의 결과가 알림뿐이다. 알림을 받은 쪽이 바쁘거나 한도에 걸리면 아무 일도 없다.
3. 닫는 길에 증거가 필요 없다. 사유 한 줄이면 닫힌다.

## 원칙

- 글로 된 규칙을 두지 않는다. 장치가 거절하거나, 장치가 직접 한다.
- 3층이 할 일은 지시서를 써서 등록하는 것과 결과를 확인해 닫는 것뿐이다.
- 닫기는 증거가 있을 때만 된다. 증거는 결과 주소이거나 사람 소유자의 확인 글이다.

## 항목의 꼴

역할별 장부 파일 `.agents/work/ledger/<역할>.json` 의 항목에 다음 칸을 더한다.
기존 칸(id, title, from, due, status, worker, checked_at, note)은 그대로다.

| 칸 | 뜻 |
| --- | --- |
| `prompt` | 지시서 파일의 절대 경로. 일꾼이 이 글만 읽고 일할 수 있어야 한다 |
| `result_file` | 일꾼이 결과를 쓰는 파일의 절대 경로 |
| `model` | 일꾼 모델 이름 |
| `cwd` | (선택) 일꾼이 도는 폴더 |
| `registered_at` | 지시서를 붙인 시각 |
| `run` | 마지막 일꾼: pid, 커널 시작 시각, 시작·끝 시각, 띄운 횟수, 로그 경로 |
| `closed` | 닫은 기록: `by: result` 와 결과 주소, 또는 `by: owner` 와 확인 글 번호·글쓴이 |
| `alerts` | 알림 사유별 마지막 시각(같은 알림을 되풀이하지 않기 위함) |

파일 판(version)은 1 로 둔다. 더한 칸은 모르는 쪽이 무시하므로 같은 파일을 읽는
다른 도구가 그대로 돈다.

## 관문

| 관문 | 동작 |
| --- | --- |
| 등록 | `add` 는 지시서 파일이 없거나 비었거나 보통 파일이 아니면 거절한다. 결과 파일 경로와 모델이 없어도 거절한다. 결과 파일이 이미 있으면 거절한다(옛 결과로 바로 닫히는 것을 막는다) |
| 기한 넘김 | `tick` 이 일꾼이 없고 결과도 없는 항목에 그 지시서로 일꾼을 띄운다. 3층에게는 알림 파일만 남긴다 |
| 중복 | 일꾼이 살아 있으면(같은 pid 이고 커널 시작 시각이 같음) 다시 띄우지 않는다 |
| 닫기 | `drop` 명령이 없다. `done` 은 `--result` 가 내용 있는 파일이거나 http(s) 주소일 때만 된다. `confirm` 은 소유자가 쓴 글이 그 항목을 가리킬 때만 된다 |
| 뒷문 닫기 | 지시서가 붙은 항목이 닫은 기록 없이 `done`·`dropped` 로 바뀌어 있으면 `tick` 이 다시 열고 알린다. 파일을 직접 고쳐도 일은 계속 굴러간다 |
| 기한 옮기기 | 기한을 바꾸는 명령이 없다. 새 항목을 올려도 옛 항목은 열린 채 굴러간다 |
| 디스크 | 여유 공간이 문턱 아래면 띄우지 않고 알린다 |

## 소유자 확인

`confirm <id> --channel --msg-id` 는 메신저에서 그 글을 받아 와 두 가지를 본다.
글쓴이가 설정의 `owner_ids` 에 있는가. 글 본문에, 또는 그 글이 답한 글 본문에
항목 id 앞 여덟 글자가 있는가. 3층이 "장부 c7aac232 닫아도 될까요"라고 묻고
소유자가 그 글에 답하면 둘째 조건이 채워진다. 소유자가 id 를 외울 필요가 없다.

## 일꾼 띄우기

- 명령은 설정의 `worker.command` 이다. `{model}` 자리에 항목의 모델이 들어간다.
  표준 입력으로 머리말(항목 id, 제목, 결과 파일, 지시서 경로)과 지시서 본문이 간다.
- 일꾼은 떼어 낸 프로세스로 뜬다. `tick` 은 기다리지 않고 끝난다.
- 결과 파일의 윗폴더는 띄우기 전에 만든다.
- 일꾼이 결과 없이 죽으면 `retry_min` 뒤 다시 띄운다. `max_attempts` 번을 넘으면
  더 띄우지 않고 알린다. 모델 한도나 깨진 지시서로 토큰을 끝없이 쓰는 것을 막는다.
  고친 뒤 `start <id>` 로 다시 띄운다.
- 동시에 도는 일꾼은 `max_parallel` 까지다. 나머지는 기한이 이른 순서로 기다린다.
  밀린 항목이 많은 장부를 처음 켤 때 한꺼번에 뜨는 것을 막는다.
- `tick` 은 항목을 닫지 않는다. 결과 파일이 생기면 `result-ready` 알림만 보낸다.
  결과를 읽고 닫는 것은 3층의 일이다.
- 3층이 기한 전에 직접 띄울 때도 `start` 를 쓴다. 다른 길로 띄운 일꾼은 `attach`
  로 적는다. 그래야 `tick` 이 겹쳐 띄우지 않는다.

## 서버 차이

모두 설정 파일에 둔다: 역할 목록, 일꾼 명령과 허용 권한, 모델 목록, 동시 수·재시도,
디스크 경로와 문턱, 알림 폴더와 알림 명령, 소유자 id 와 토큰 환경 변수 이름.
코드는 서버마다 같다.

## 정한 것과 이유

- **기존 장부 파일 꼴을 그대로 쓴다.** 이미 돌고 있는 장부의 열린 항목을 변환 없이
  옮길 수 있고, 켠 뒤 되돌려도 파일이 그대로 읽힌다.
- **옛 닫힌 항목은 건드리지 않는다.** 지시서가 없는 항목은 닫혀 있으면 그대로 둔다.
  되여는 것은 지시서가 붙은 항목뿐이다.
- **결과 주소의 주소(URL)는 모양만 본다.** 받아 와서 확인하지 않는다. 닫은 기록에
  남으므로 사람이 눌러 볼 수 있다.
- **너무 오래 도는 일꾼은 죽이지 않고 알린다.** 긴 작업을 장치가 끊으면 더 큰 손해다.

## 한계

- 같은 계정으로 설정 파일을 고칠 수 있으면 소유자 목록도 바꿀 수 있다. 설정 파일은
  다른 호스트 정책 파일과 같은 보호 아래 둔다.
- 잠금은 `flock`, 일꾼 식별은 `/proc` 을 쓴다. 리눅스 밖에서는 pid 확인으로 물러선다.
- 일꾼이 결과 파일에 무엇을 썼는지는 보지 않는다. 내용 검수는 닫는 쪽의 일이다.

HTTP 서버가 돌려준다.

| 시험 | 확인하는 것 |
| --- | --- |
| registration without a usable instruction file is refused | 지시서 없음·없는 파일·빈 파일·결과 파일 없음·모델 없음 모두 거절, 장부 파일이 생기지 않음 |
| an overdue item starts a worker… | 기한 넘긴 항목만 뜸, 모델 인자, 입력에 지시서 본문과 결과 경로, 알림 파일 하나 |
| a running worker is not started twice… | 살아 있는 동안 두 번 더 돌려도 한 번만 뜸, 죽은 뒤 다시 뜸, 상한 뒤 안 뜸 |
| the parallel limit queues the rest… | 동시 수 상한, 결과가 있으면 다시 안 뜸, 항목은 열린 채 |
| drop is refused… | `drop` 거절, 파일을 직접 `dropped`·기록 없는 `done` 으로 고쳐도 다시 열림 |
| done needs a real result address | 주소 없음·없는 파일 거절, 있는 파일과 URL 로 닫힘 |
| an owner confirmation message closes an item… | 남의 글·id 없는 글·없는 글 거절, 소유자 글과 답글로 닫힘, 닫힌 뒤 안 뜸 |
| low free space starts nothing and notifies | 문턱 아래면 안 뜸, 알림 한 번, `start` 도 거절 |
| an existing row without an instruction… | 옛 항목은 알림만, `adopt` 뒤 뜸, 옛 닫힌 항목은 그대로 |
| start and attach… | 미리 띄우거나 적어 둔 일꾼이 있으면 `tick` 이 더 띄우지 않음 |
