# ADK Worker Guard Rails (Unit 1) - Design Document

## Scope
Implementation of process compliance guard rails for ADK workers:
1. Mandatory work card identification.
2. Evidence required for completion ("done").
3. Model quota enforcement based on profile.

## Guard Rails

### 1. Mandatory Work Card
- **Requirement**: Worker must receive a valid, open work card number on startup.
- **Enforcement**: Executor (`spawn-worker.mjs`, `launch.mjs`, `cli.mjs`) checks the ledger (`.agents/work/ledger/*.json`).
- **Failure**: Reject startup if card missing or closed/invalid.

### 2. Evidence Required for "Done"
- **Requirement**: Command to mark card as `done` must provide evidence (file path, URL, or commit SHA).
- **Enforcement**: Validate evidence in `done` command/script (`scripts/ledger/`).

### 3. Model Quota Enforcement
- **Requirement**: Limit number of concurrent workers per model family.
- **Enforcement**: Check profile for upper bound per model family.
- **Failure**: Reject if quota exceeded.

## Exclusions
- Signature keys
- Digest chains
- OS-level blocking
- Provider limit signaling
- 3rd-layer fallback
