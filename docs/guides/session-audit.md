# 세션 감사

세션 감사는 작업 과정에서 반복 검토, 우선순위 지연, 관문 변경과 깨움 적체를 관찰한다. 실행 상태는 [session-health](session-health.md), 사람의 응답은 [response-watch](response-watch.md)가 별도로 관찰한다. 감사는 세션을 종료하거나 작업을 자동으로 막지 않는다. 현재 입력은 정규화된 JSON 픽스처이며, 실제 세션을 수집해 이 형식으로 만드는 어댑터와 타이머 설치는 운영 환경에서 별도로 준비해야 한다.

## 관찰 신호

| 신호 | 관찰하는 근거 |
| --- | --- |
| S1 | 계획별 리뷰 파일 수와 시각 |
| S2 | 리뷰 결과와 차단 항목 수의 변화 |
| S3 | 우선순위 작업의 근거가 마지막으로 갱신된 시각 |
| S4 | 시간별 도구 호출 수 |
| S5 | 관문 파일 변경과 관련 커밋 |
| S6 | FAIL 또는 NOT-READY 리뷰의 시각 |
| S7 | 소비하지 않은 깨움 파일 수와 최고령 |
| S8 | 작업 장부의 상태와 승인 대기 근거 |
| S9 | 제한된 우선순위 제목·항목과 원문의 불일치 판정 |
| S10 | 정규화 기록의 상한 관련 표지 시각 |

S1~S8과 S10은 결정론적으로 수집한다. S9는 선택적인 모델 판정이며 경고만 낸다. 세션 원문은 모델에 보내지 않는다. 읽지 못한 입력은 보고서에 따로 표시하고 정상이라고 단정하지 않는다. 핵심 입력을 연속해서 충분히 읽지 못하면 `audit-blind`를 보고한다.

반복 리뷰, 우선순위 지연, 관문 변경, 깨움 적체가 감지되면 코드와 대상별 사건으로 추적한다. 같은 사건은 경고와 보고를 각각 최대 한 번 보내고, 회복은 보고서에만 남긴다. 검증되지 않은 방식 변경 주장은 셈을 초기화하지 않는다. 사람 승인이나 독립된 리뷰 등은 신뢰할 수 있는 검증기가 확인한 경우에만 초기화 근거가 된다.

`thresholds.reviewCap` 기본값 6은 반복 리뷰를 발견하기 위한 **경고 임계값**이다. 하네스북의 코드 수정 리뷰 상한 2회와 목적이 다르며, 6회까지 수정해도 된다는 허가가 아니다. `dailyCap` 기본값 6은 역할별 하루 발신 상한이다. 상한에 이르면 별도 보고 한 건을 보내고 나머지는 다음 날까지 보류한다.

## 설정과 실행

[설정 예시](../../config/session-audit.example.json)를 비공개 위치에 복사하고 모든 자리표시자를 바꾼다. `roles[].sessionDirs`에는 감사 대상의 모든 세션 디렉터리를 넣는다. `stateFile`, `reportFile`, 각 `wakeDir`, `schedule.file`은 절대 경로이며 서로 겹치거나 세션 디렉터리 안팎으로 중첩되어서는 안 된다. 심볼릭 링크가 가리키는 위치도 검사한다. `hold: true`는 허용된 쓰기 범위 밖에 파일을 만들기 때문에 거부한다.

`schedule.id`는 [정기 일정 장부](regular-schedule-ledger.md)의 행 ID와 같아야 한다. 장부의 일정은 실제 설치 전까지 제안 상태로 둔다. 장부 감시는 현재 일별·주별 일정을 지원한다. 30분 실행 타이머를 사용하더라도 예시의 일별 행은 일별 누락만 감지하므로 더 짧은 누락 감시에는 별도 지원이 필요하다.

`timezone`과 `night.start`·`night.end`는 보고의 야간 채널 구간을 정한다. 경고는 내부 채널로, 보고는 시간대에 따라 주간 또는 야간 채널로 간다. `judge.runner`는 `none`, `codex`, `agy` 중 선택한다. `none`은 모델을 호출하지 않고 고정 문장을 쓴다. 발신 토큰 값은 설정 파일에 넣지 않고 `sender.tokenEnv`가 가리키는 환경 변수로 공급한다. 토큰이 없거나 `--dry`를 쓰면 발신과 깨움 파일 생성 없이 보고서에 예정 내용을 남긴다.

```sh
node scripts/session-audit.mjs --run --config <private-config> --fixture <normalized-input-dir> --role <role> --dry
node scripts/session-audit.mjs --config <private-config> --fixture <normalized-input-dir> --dry --at <ISO-time>
```

모든 명령 실행에는 설정과 장부가 필요하다. 성공과 실패 모두 장부에 기록한다. 기록할 수 없으면 감사 명령은 종료 코드 2로 실패한다. 감사 자체의 실패는 기록 성공 시 코드 1이다. 설정 자체를 읽지 못하거나 안전한 기록 경로를 확인할 수 없는 경우 기록은 불가능하며 코드 2로 종료한다. `schedule-record.mjs`를 직접 실행할 때의 실패 코드는 1이다. 장부의 실패 기록은 실행 사실만 뜻하며 감사 성공을 뜻하지 않는다.

상태가 손상되면 초기화하지 않고 중단한다. 발신 의도는 전송 전에 저장하며 결과가 불확실하면 자동 재발신하지 않는다. 고장 난 입력과 장부, 발신 결과를 확인하고 원인을 고친 뒤 다시 실행한다. `--dry`는 발신과 상태 파일을 변경하지 않지만 보고서와 일정 장부는 기록한다.

## 사람이 확인하고 알림을 멈추는 방법

보고서와 근거를 확인해 실제 문제를 해결하거나 담당자가 판단을 기록한다. 문제 조건이 해소되면 사건이 회복되고 같은 사건의 알림은 더 발송되지 않는다. 단순 답글이나 장부 갱신은 해결 증거가 아니다. 사람 승인이 필요한 경우 해당 대상에 연결된 승인 근거를 남기고 독립 검증 절차에서 확인한다. 일시 중지는 운영자가 해당 타이머를 중지해 수행하며, 이 경우 장부 누락 경고가 생길 수 있다. 불확실한 발신은 채널에서 실제 수신 여부를 확인한 뒤 상태를 백업하고 해당 영수증만 조정한다.
