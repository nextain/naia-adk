# Naia ADK 시작하기

이 작업 공간에서는 AI와 이야기하며 일합니다. 할 일을 사람에게 부탁하듯 말하면 AI가 회사 문서와 절차를 읽고 일을 합니다. 다른 기기나 다른 AI에게 넘길 일은 AI가 작업 대기열에 올리고, 사람이 봐야 할 문서가 생기면 AI가 "이 문서를 봐 주세요" 하고 확인을 요청합니다.

사람이 할 일은 세 가지입니다. AI에게 말로 맡기고, 브라우저의 대시보드에서 진행을 보고, AI가 봐 달라고 한 문서를 읽고 답합니다. 명령어를 외울 필요는 없습니다.

## 작업 공간의 모양

작업 공간은 naia-adk를 받은 폴더 하나입니다. 그 안에 두 가지를 더 받습니다.

- `data-company/` 아래에 회사 문서를 받습니다. 온보딩, 회사 소개, 업무 절차가 들어 있습니다.
- `projects/` 아래에 회사가 함께 쓰는 협업 프로젝트를 받습니다. 작업 대기열과 작업보드가 여기에 있습니다.

AI는 늘 맨 위 폴더(naia-adk를 받은 폴더)에서 띄웁니다. 그래야 AI가 회사 문서와 협업 프로젝트를 한꺼번에 보고, 작업 공간의 규칙을 따릅니다. `projects/` 안으로 들어가서 띄우지 않습니다.

## 처음 한 번 준비하기

컴퓨터에 네 가지가 필요합니다. Git, Node.js 22 이상, pnpm 9 이상, 그리고 AI 도구(Claude Code 또는 Naia 앱)입니다. 어떻게 까는지 모르면 AI 도구부터 설치하고, 아무 폴더에서 띄운 뒤 이 문서를 보여 주며 "이대로 설정해 줘"라고 하면 됩니다. 아래 명령은 AI가 대신 칠 수 있고, 직접 하고 싶은 사람을 위해 적어 둡니다.

1. 작업 공간을 받습니다. Naia 앱을 쓰면 첫 설정 화면이 받아 줍니다. 직접 받으려면 다음과 같이 합니다.

   ```bash
   git clone https://github.com/nextain/naia-adk.git
   cd naia-adk
   ```

2. 받은 작업 공간을 내 비공개 저장소로 옮깁니다. ADK는 누구나 보는 공개 저장소라서, 내 작업 기록과 회사 설정이 밖으로 나가지 않게 하려는 것입니다. GitHub 같은 곳에 비공개 저장소를 하나 만든 뒤 다음을 실행합니다. 공개 ADK는 `upstream`이라는 이름으로 남아서, 나중에 새 기능을 받아 올 수 있습니다.

   ```bash
   git remote rename origin upstream
   git remote add origin <내 비공개 저장소 주소>
   git push -u origin main
   ```

3. 회사 문서를 연결합니다. 회사 문서 저장소 주소는 회사 관리자에게 받습니다. 이 명령은 회사 문서를 `data-company/` 아래에 받고, 회사가 정해 둔 협업 프로젝트를 `projects/` 아래에 함께 받습니다. 이미 받아 둔 폴더는 덮어쓰지 않습니다.

   ```bash
   pnpm install
   pnpm adk:setup -- --company <회사 문서 저장소 주소>
   ```

## 매일 일하는 방법

### 대시보드 열기

작업 공간 폴더에서 `./start.sh`(Windows는 `start.bat`)를 실행하고, 브라우저로 `http://localhost:3142/docs`를 엽니다. 주소는 이것 하나만 기억하면 됩니다.

- 위쪽 "문서" 탭에서 회사 문서를 읽습니다. 온보딩, 회사 소개, 업무 절차가 여기에 있습니다.
- 위쪽 "작업" 탭에서 AI에게 맡긴 일이 어디까지 왔는지 봅니다. 화면은 "진행 중", "확인 필요", "최근 끝남" 세 칸으로 나뉩니다.

### AI에게 말로 맡기기

작업 공간 맨 위 폴더에서 AI를 띄웁니다. Claude Code는 그 폴더에서 터미널을 열고 `claude`를 실행하고, Naia 앱은 그 폴더를 작업 공간으로 고릅니다. AI는 시작할 때 작업 공간의 규칙 파일을 스스로 읽기 때문에, 따로 설명하지 않아도 회사 절차를 압니다.

그다음은 사람에게 부탁하듯 말하면 됩니다.

> 온보딩 문서를 읽고 내가 첫 주에 할 일을 정리해 줘.

> 이번 주 콘텐츠 기획을 같이 정하자. 정해지면 작업 대기열에 올려 줘.

> 어제 맡긴 일 어디까지 됐어?

일을 대기열에 올릴지, 다른 기기에 맡길지는 AI가 절차에 따라 판단하고 사람에게 묻습니다. 사람이 대기열 파일이나 명령을 직접 다룰 일은 없습니다.

### AI가 봐 달라고 한 문서 확인하기

AI는 사람이 정해야 하는 일이 생기면 그 내용을 문서로 정리하고 확인을 요청합니다. 요청은 작업 탭의 "확인 필요" 칸에 뜹니다. 카드의 "문서 보기"를 누르면 문서 탭에서 그 문서가 열립니다. 읽고 나서 AI에게 "이 문서 봤어, 이렇게 가자"처럼 말로 답하면 됩니다.

### 최신 내용 받기

하루를 시작할 때 AI에게 "최신으로 받아 줘"라고 하거나, 직접 다음을 실행합니다. 작업 공간, 회사 문서, 협업 프로젝트를 한 번에 최신으로 받습니다. 고치던 파일이 있는 저장소는 내용이 섞이지 않게 건너뛰고 알려 줍니다.

```bash
pnpm adk:setup -- --pull
```

## 회사 관리자라면

대시보드에 어떤 회사 문서 폴더를 보여 줄지, 어떤 공동 프로젝트를 함께 받게 할지는 회사 문서 저장소의 `adk-company.json` 한 파일로 정합니다. 쓰는 법은 [회사 설정 파일 안내](company-config.ko.md)에 있습니다.
