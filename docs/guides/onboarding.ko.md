# Naia ADK 온보딩 가이드: 팀과 AI가 함께 일하는 워크스페이스 시작하기

이 가이드는 Naia ADK(AI Development Kit, 인공지능 개발 도구 모음)를 내려받아 개인 저장소로 구성하고, 회사의 공유 문서 및 프로젝트를 연동하여 사람과 AI가 한 공간에서 협업하는 전체 과정을 안내합니다.

개발자든 비개발자(기획자, 마케터 등)든 같은 절차를 거쳐 환경을 구성할 수 있습니다. 사람은 웹 브라우저 대시보드의 문서와 작업 화면을 통해 업무를 파악하고, Claude Code나 Naia 같은 AI 에이전트는 동일한 파일 시스템을 직접 읽어 컨텍스트를 이해하고 함께 일합니다.

---

## 1. 사전 준비물

작업을 시작하기 전에 컴퓨터에 다음 도구들이 설치되어 있어야 합니다.

1. **Git**(깃): 코드와 문서의 변경 이력을 관리하고 저장소를 복제하기 위한 분산 버전 관리 시스템입니다.
2. **Node.js 22 이상**: 자바스크립트 및 서버 코드를 실행하는 런타임 환경입니다. 터미널에서 `node -v` 명령으로 버전을 확인합니다.
3. **pnpm 9 이상**: 패키지를 빠르고 효율적으로 관리하는 패키지 매니저입니다. 설치되어 있지 않다면 `npm install -g pnpm`으로 설치합니다.
4. **AI 에이전트 도구**: 터미널에서 작업하는 **Claude Code** 또는 데스크톱 애플리케이션인 **Naia 앱** 중 하나를 준비합니다.

---

## 2. naia-adk 워크스페이스 받기

두 가지 방법 중 편한 방식으로 워크스페이스를 내려받습니다.

- **Naia 앱을 사용하는 경우**: Naia 앱 초기 설정 시 안내에 따라 워크스페이스 폴더를 내려받습니다.
- **직접 클론하는 경우**: 터미널을 열고 다음 명령어를 실행하여 공개 저장소를 복제합니다.

```bash
git clone https://github.com/nextain/naia-adk.git
cd naia-adk
```

---

## 3. 본인의 비공개 저장소로 올리기

ADK는 기본 틀을 제공하는 공개 저장소입니다. 본인이 진행할 작업 내역이나 회사 관련 설정이 공개되지 않도록, GitHub나 GitLab 등에 본인만의 비공개(Private) 저장소를 새로 만들고 그곳으로 원격 저장소 주소를 변경합니다.

```bash
# 기존 공개 저장소 원격 이름을 upstream으로 바꿉니다.
git remote rename origin upstream

# 새로 만든 본인의 비공개 저장소 주소를 origin으로 추가합니다.
git remote add origin <본인 비공개 저장소 주소>

# 본인 저장소의 main 브랜치로 코드를 올립니다.
git push -u origin main
```

이후 공개 저장소에 새로운 기능이나 버그 수정이 업데이트되었을 때는 다음 명령으로 최신 변경 사항을 본인 브랜치에 안전하게 병합할 수 있습니다.

```bash
git fetch upstream
git merge upstream/main
```

## 4. 의존성 설치 및 회사 설정하기

워크스페이스 디렉터리 안에서 의존 패키지를 설치하고, 회사 설정 명령을 실행합니다.

```bash
# 프로젝트 의존성을 설치합니다.
pnpm install

# 회사 문서 저장소를 연동합니다.
pnpm adk:setup -- --company <회사 문서 저장소 주소>
```

이 명령은 다음과 같은 작업을 자동으로 처리합니다:

1. 지정한 회사 문서 저장소를 `data-company/<저장소이름>` 디렉터리에 복제합니다. 이미 폴더가 있다면 기존 내용을 보호하기 위해 덮어쓰지 않고 건너뜁니다.
2. 회사 문서 저장소 안의 `adk-company.json` 설정 파일을 읽어, 회사가 지정한 프로젝트 저장소들(`projects/<프로젝트명>`)을 필요한 경로에 자동으로 복제합니다.

만약 어떤 작업이 실행될지 미리 확인해보고 싶다면 `--dry-run` 플래그를 붙여 테스트할 수 있습니다.

```bash
pnpm adk:setup -- --company <회사 문서 저장소 주소> --dry-run
```

## 5. 서버와 대시보드 실행하기

설정이 끝나면 런처 스크립트를 실행하여 대시보드와 API 서버를 실행합니다.

- **Linux 및 macOS**:
  ```bash
  ./start.sh
  ```
- **Windows**:
  ```cmd
  start.bat
  ```

터미널에 표시되는 주소로 브라우저를 엽니다:
- **대시보드 메인**: `http://localhost:3142`
- **회사 문서 포털**: `http://localhost:3142/docs`
- **작업 보드**: 대시보드 상단 내비게이션의 **작업** 탭을 클릭하거나 회사에서 지정한 포트로 바로 접속합니다.

대시보드 상단의 **문서** 탭에서는 회사 문서와 프로젝트 문서가 트리 형태로 정돈되어 표시됩니다. 필요한 문서를 클릭하여 내용을 확인하고, 문서 내 링크와 이미지를 통해 빠르게 업무 내용을 파악할 수 있습니다.

---

## 6. AI 에이전트와 함께 일하기

환경이 준비되면 AI 도구를 실행하여 협업을 시작합니다. ADK 루트 디렉터리(맨 위 폴더)에서 터미널을 열고 다음 중 하나를 실행합니다.

- **Claude Code 사용 시**: 터미널에서 `claude`를 실행합니다.
- **Naia 앱 사용 시**: Naia 앱에서 현재 ADK 디렉터리를 워크스페이스로 선택합니다.

AI는 세션이 시작될 때 워크스페이스 루트의 `AGENTS.md` 파일부터 차례대로 읽어, 이 저장소의 규칙, 파일 구조 표준, 작업 흐름, 공개 권한 정책을 자동으로 파악합니다.

사용자는 사람에게 설명하듯 편하게 요구사항을 전달하면 됩니다. 예를 들어 "01. 온보딩 문서를 읽고 내가 오늘 해야 할 개발 환경 설정을 요약해 줘"라거나 "공동작업 허브의 최근 이슈 목록을 정리해 줘"라고 요청하면 AI가 동일한 문서를 직접 읽고 분석하여 지원합니다.

---

## 7. 워크스페이스 최신 상태로 유지하기

회사 문서나 연계 프로젝트가 업데이트되었을 때는 `--pull` 옵션을 사용하여 모든 연동 저장소를 한 번에 최신 상태로 가져옵니다.

```bash
pnpm adk:setup -- --pull
```

이 명령은 ADK 루트 저장소, `data-company/` 아래의 회사 문서 저장소, 그리고 `projects/` 아래의 모든 연계 프로젝트 저장소를 확인합니다. 작업 중이던 파일이 변경되어 작업 트리가 깨끗하지 않은 경우에는 충돌을 방지하기 위해 해당 저장소의 업데이트를 안전하게 건너뛰고 안내 문구를 출력합니다.

## 8. 회사 관리자 안내: `adk-company.json` 설정 파일 작성법

회사 관리자는 회사 문서 저장소의 최상위 디렉터리에 `adk-company.json` 파일을 작성하여, 구성원들의 대시보드에 노출할 문서 폴더와 자동으로 받아올 프로젝트 목록을 선언할 수 있습니다.

기본적으로 회사 문서는 비공개 원칙이며, `docs.include`에 명시된 폴더만 대시보드에 안전하게 노출됩니다.

### 설정 파일 예시

```json
{
  "schemaVersion": 1,
  "title": "회사 문서",
  "docs": {
    "include": [
      "01. 온보딩",
      "05. 브랜드·마케팅"
    ]
  },
  "repos": [
    {
      "id": "hub",
      "path": "projects/hub",
      "remote": "https://github.com/example/hub.git",
      "docs": {
        "title": "공동작업 허브",
        "include": ["docs"]
      }
    }
  ],
  "board": {
    "repo": "hub",
    "script": "scripts/board-server.mjs",
    "port": 8894
  }
}
```

### 각 항목 설명

- **schemaVersion**: 설정 스키마의 버전 번호입니다. 숫자 1로 지정합니다.
- **title**: 대시보드 문서 목록에 표시될 회사 문서 영역의 대표 제목입니다.
- **docs.include**: 회사 문서 저장소 안에서 대시보드에 공개할 폴더 이름 목록입니다. 여기에 적히지 않은 폴더는 대시보드 트리와 API 조회에서 자동으로 제외(404)됩니다.
- **repos**: 팀원들이 공통으로 내려받아야 할 프로젝트 저장소 목록입니다.
  - **id**: 프로젝트를 구분하는 고유 식별자입니다.
  - **path**: ADK 루트 기준 상대 경로이며, 보안을 위해 반드시 `projects/` 또는 `data-company/` 아래 경로만 허용됩니다. 상위 경로(`..`)나 절대 경로는 거부됩니다.
  - **remote**: 복제할 원격 Git 저장소 주소입니다.
  - **docs**: 해당 프로젝트 내부의 문서를 대시보드에 포함할 때 사용합니다. `title`로 제목을 지정하고 `include`로 노출할 폴더 목록을 지정합니다.
- **board** (선택 사항): 회사의 공동 작업 보드 서버 설정입니다.
  - **repo**: 보드 서버 스크립트가 들어 있는 저장소의 id(위 `repos`에 선언된 id 중 하나)입니다.
  - **script**: 실행할 보드 서버 스크립트의 상대 경로입니다.
  - **port**: 보드 서버가 사용할 포트 번호입니다. 설정 시 `pnpm dev` 실행 시 보드 서버가 함께 구동되며 대시보드 상단의 '작업' 탭을 통해 즉시 접속할 수 있습니다.
