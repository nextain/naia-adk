# 게시 확인과 승인

문서의 저장된 판으로 게시 확인을 요청하고, 담당자가 서버 미리보기를 확인한 뒤 승인할 수 있습니다. 승인은 고정된 자료와 Ed25519 영수증을 보관하며 외부 사이트에 실제 게시하지는 않습니다. 승인 뒤 문서·그림·설정이 바뀌면 새 확인 요청이 필요합니다.

## 설정

게시 기능을 사용하지 않으면 설정하지 않아도 됩니다. 현재 프로세스 간 잠금은 `flock` 명령이 필요하며, 사용할 수 없으면 잠금이 필요한 작업을 거절합니다. 사용하려면 API 서버에 다음 환경 변수를 설정합니다.

- `PUBLISH_STATE_DIR`: 문서 출처 밖의 절대 경로. 소유자만 접근할 수 있는 디렉터리에 게시 설정과 불변 기록을 둡니다.
- `PUBLISH_SIGNING_KEY_FILE`: 게시 저장소, 문서 출처, 모든 Git 작업 트리 밖의 소유자 전용 Ed25519 개인키 파일. 심볼릭 링크는 사용할 수 없습니다.
- `PUBLISH_SIGNING_KEY_ID`, `PUBLISH_PUBLIC_KEYS`: 개인키 식별자와 `{식별자: PEM 공개키}` JSON. 공개키가 개인키와 일치해야 합니다.
- `PUBLISH_GATEWAY_SCOPE`: 계정의 범위 식별자. 대시보드와 서버가 같은 값을 사용합니다.
- `PUBLISH_APPROVER_IDS`: 승인 담당자 계정 전체 식별자를 쉼표로 구분한 목록. 각 항목은 `<범위>:<계정>` 형식입니다.
- `PUBLISH_GATEWAY_OVERWRITE_CONFIRMED=1`: 관문이 외부 계정 헤더를 제거하고 검증된 로그인 계정으로 덮어쓰는지 실제로 확인한 뒤에만 대시보드와 서버 모두에 설정합니다.

대시보드는 별도로 `NAIA_GATE_SECRET_FILE`을 사용해 관문의 공유 비밀을 검증합니다. 관문은 매 요청의 `x-ax-account-key`를 검증된 계정 키로 덮어써야 합니다. 비밀만 전달하면서 외부 계정 헤더를 그대로 남기는 관문은 신원을 보증하지 않습니다. 계정 키는 영문 소문자로 시작하는 소문자·숫자·붙임표 2~32자입니다. 운영 신원과 키를 코드나 시험 자료에 넣지 않습니다.

게시 설정은 `PUBLISH_STATE_DIR/descriptors/<slug>.json`에 둡니다. 설정에는 `source`, `path`, `slug`, `body_selector`, `frontmatter`, `asset_roots`, `asset_path_map`, `media_map`이 필요합니다. `source`와 `path`는 등록된 문서 출처와 그 출처의 상대 경로입니다. 본문 시작·끝 제목과 구분자를 정확히 지정하고, 게시에 필요한 이미지와 언어별 미디어를 등록합니다. 대상 식별자는 현재 `site-a`, `site-b`이며 실제 사이트 전송 설정이 아닙니다. `site-b`의 분류는 `secondary_category`로 지정합니다. 허용하지 않은 필드, 누락된 본문·이미지, 외부 이미지 또는 경로 이탈은 거절됩니다.

## 사용

1. 등록된 문서를 열고 저장되지 않은 편집을 저장합니다. 표시된 문서와 서버 저장판이 다르면 문서를 다시 엽니다.
2. **게시 확인 요청**을 누르고 확인 화면을 엽니다. 요청은 선택한 판과 담당자 목록을 함께 고정합니다.
3. 담당자는 **게시 확인 할 일**에서 대기 항목의 요청판을 열어 본문·그림·대상·언어를 확인하고 **게시 확인**을 누릅니다. 목록은 로그인한 담당자에게 할당된 요청만 보여 주며 대체된 요청과 완료된 요청을 구분합니다.
4. 승인 결과에서 승인판과 영수증을 확인합니다. 완료는 승인 확정 기록에서 계산됩니다. 응답이 유실되면 화면의 같은 요청 재시도로 원래 멱등키와 본문을 사용합니다.

서버는 요청과 승인 때 신원·문서 권한을 다시 확인하고 요청판 지문을 대조합니다. 변경된 판의 승인은 거절합니다. 고정된 승인판과 영수증은 이후 초안이 변경되어도 확인할 수 있습니다. 저장소 오류나 조회 실패는 빈 성공 목록으로 취급하지 않습니다.
