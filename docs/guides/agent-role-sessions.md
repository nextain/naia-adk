범위: 공통
상태: 1판. 그룹 뼈대(`templates/group-skeleton/agents/`)의 에이전트 자리를 실제 세션으로 돌리는 방법. 봇 깨움 연결과 에이전트별 작업 폴더는 다음 판에서 채움

# 역할 세션 운영

그룹 ADK 의 에이전트 자리(`agents/<id>-adk/`)마다 AI 에이전트 세션 하나를 그룹 개발 서버에 상시로 띄우고 역할을 주는 방법입니다. 자리와 매니페스트 규칙은 `templates/group-skeleton/agents/README.md` 에 있고, 이 문서는 세션을 띄우고 기록하는 일만 다룹니다.

## 1. 구성

- 그룹 개발 서버 한 대에 역할 세션 여럿(예: 개발·마케터·사업·지원)을 띄웁니다.
- 칸을 나눌 수 있는 터미널 관리 도구를 씁니다. 아래 예는 `herdr` 명령입니다. 한 탭 안에 역할마다 칸 하나, 칸마다 에이전트 세션 하나를 둡니다.
- 역할 세션은 자기 에이전트 자리의 역할 문서(`agents/<id>-adk/index.md`)를 읽고 일합니다.

## 2. 띄우는 법

1. 서버의 탭에서 칸을 나누고 칸마다 에이전트 세션을 실행합니다.
2. 칸 번호를 확인합니다.

   ```bash
   herdr pane list
   ```

3. 칸마다 역할을 정하고 사람이 알아볼 이름을 붙입니다. 칸 번호는 다시 띄우면 바뀔 수 있으므로 이름을 꼭 붙입니다.

   ```bash
   herdr pane rename <칸> <이름>-<역할>
   ```

4. 칸 정보를 읽어 세션 식별값을 확인하고 기록합니다(4절).

   ```bash
   herdr pane get <칸>
   ```

## 3. 역할 주는 법

1. 역할 문서를 서버의 작업 저장소 밖(예: `~/<그룹>-agents/<id>/index.md`)에 복사합니다. 작업 저장소를 다른 세션과 함께 쓰는 동안 그 저장소 상태를 건드리지 않기 위해서입니다.
2. 첫 지시는 한 줄로 보냅니다. 글을 넣고 1초 뒤 엔터를 따로 보냅니다.

   ```bash
   herdr pane send-text <칸> "<한 줄 지시>"
   # 1초 뒤
   herdr pane send-keys <칸> enter
   ```

   첫 지시에 넣을 것: 이름과 역할, 읽을 역할 문서 경로, "맡은 일·보는 채널·하지 않는 일을 짧게 답하고 다음 지시를 기다려라", "지시 전에는 파일 수정·git·배포를 하지 마라".
3. 답을 읽어 역할을 제대로 받았는지 확인합니다.

   ```bash
   herdr pane read <칸> --source recent-unwrapped --lines 40
   ```

## 4. 기록하는 법

세션을 띄우거나, 다시 띄우거나, 닫을 때마다 그룹 ADK 의 두 곳을 함께 고칩니다.

- 에이전트를 모은 문서 맨 위 세션 표: 이름·역할·칸(번호와 이름)·세션 식별값·상태
- 각 `agents/<id>-adk/index.md` 의 "세션" 절

"세션" 절 틀:

```markdown
## 세션

- **서버**: <그룹 개발 서버 이름>
- **자리**: <도구 세션> → <작업 공간> → <탭> → 칸 `<칸>` (칸 이름 `<이름>-<역할>`)
- **세션 식별값**: `<식별값>`
- **시작**: <띄운 시각>, 역할 첫 지시 <보낸 시각>
- **작업 폴더**: <경로> (함께 쓰는 세션이 있으면 적음)
- **역할 문서 사본**: <서버 안 경로>
- **깨움·봇 연결**: <없음 또는 연결 방식>
```

칸 번호만 적지 말고 칸 이름과 세션 식별값을 같이 적습니다. 비밀값은 적지 않습니다.

## 5. 메신저 글 전달과 답글

- 봇 깨움 연결 전에는 세션이 메신저를 직접 보지 못합니다. 조정 역할이 그 역할에 관련된 글(지시·결정·질문)을 모아 세션에 넘겨 파악시킵니다.
- 원문을 그대로, 누가 언제 쓴 글인지와 함께 넘깁니다. 짧으면 한 줄 지시에 담고, 길면 역할 문서 사본 폴더에 파일로 두고 경로만 한 줄로 알립니다.
- 넘긴 글은 파악용입니다. "읽고 요약만, 행동은 지시가 온 뒤"를 함께 적습니다.
- 인사와 답글은 각 역할이 자기 봇으로 합니다. 다른 역할이나 다른 그룹의 봇으로 대신 쓰지 않습니다.

## 6. 지킬 것

- 여러 역할 세션이 같은 작업 폴더를 함께 쓰는 동안 지시 전에는 읽기만 합니다. 파일 수정·git·배포는 지시를 받은 세션만 합니다.
- 지시는 한 줄로 보냅니다. 여러 줄을 붙여 넣지 않습니다.
- 지시와 기록에 비밀값을 넣지 않습니다. 봇 열쇠는 매니페스트의 이름표(`bot.credential_ref`)로만 가리킵니다.
- 운영 서버 변경·결제·외부 발송은 사람 승인 뒤에만 합니다.
- 다른 그룹의 에이전트와 섞지 않습니다.

## 7. 아직 정하지 않은 것

1. 봇 깨움 연결: 메신저에 글이 오면 해당 역할 세션을 깨우는 연결 방식. 정해지면 매니페스트의 `bot.status` 를 `planned` 에서 `active` 로 바꿉니다.
2. 에이전트별 작업 폴더: 처음에는 여러 역할이 한 작업 폴더를 함께 쓸 수 있습니다. 역할마다 자기 자리(`agents/<id>-adk`)를 서버의 작업 폴더로 두고 역할 문서 사본을 그 안으로 옮기는 방식을 다음 판에서 정합니다.
