범위: 공통
상태: 1판. 그룹 뼈대(`templates/group-skeleton/agents/`)의 에이전트 자리를 실제 세션으로 돌리는 방법. 봇 깨움 연결과 에이전트별 작업 폴더는 다음 판에서 채움

# 역할 세션 운영

그룹 ADK 의 에이전트 자리(`agents/<id>-adk/`)마다 AI 에이전트 세션 하나를 그룹 개발 서버에 상시로 띄우고 역할을 주는 방법입니다. 자리와 매니페스트 규칙은 `templates/group-skeleton/agents/README.md` 에 있고, 이 문서는 세션을 띄우고 기록하는 일만 다룹니다.

## 1. 구성

- 그룹 개발 서버 한 대에 역할 세션 여럿(예: 개발·마케터·사업·지원)을 띄웁니다.
- 칸을 나눌 수 있는 터미널 관리 도구를 씁니다. 아래 예는 `herdr` 명령입니다. 한 탭 안에 역할마다 칸 하나, 칸마다 에이전트 세션 하나를 둡니다.
- 역할 세션은 자기 에이전트 자리의 역할 문서(`agents/<id>-adk/index.md`)를 읽고 일합니다.

## 2. 띄우는 법

1. 서버의 탭에서 칸을 나누고 칸마다 에이전트 세션을 실행합니다.
2. 칸 번호를 확인합니다.

   ```bash
   herdr pane list
   ```

3. 칸마다 역할을 정하고 사람이 알아볼 이름을 붙입니다. 칸 번호는 다시 띄우면 바뀔 수 있으므로 이름을 꼭 붙입니다.

   ```bash
   herdr pane rename <칸> <이름>-<역할>
   ```

4. 칸 정보를 읽어 세션 식별값을 확인하고 기록합니다(4절).

   ```bash
   herdr pane get <칸>
   ```

## 3. 역할 주는 법

1. 역할 문서를 서버의 작업 저장소 밖(예: `~/<그룹>-agents/<id>/index.md`)에 복사합니다. 작업 저장소를 다른 세션과 함께 쓰는 동안 그 저장소 상태를 건드리지 않기 위해서입니다.
2. 첫 지시는 한 줄로 보냅니다. 글을 넣고 1초 뒤 엔터를 따로 보냅니다.

   ```bash
   herdr pane send-text <칸> "<한 줄 지시>"
   # 1초 뒤
   herdr pane send-keys <칸> enter
   ```

   첫 지시에 넣을 것: 이름과 역할, 읽을 역할 문서 경로, "맡은 일·보는 채널·하지 않는 일을 짧게 답하고 다음 지시를 기다려라", "지시 전에는 파일 수정·git·배포를 하지 마라".
3. 답을 읽어 역할을 제대로 받았는지 확인합니다.

   ```bash
   herdr pane read <칸> --source recent-unwrapped --lines 40
   ```

## 4. 기록하는 법

세션을 띄우거나, 다시 띄우거나, 닫을 때마다 그룹 ADK 의 두 곳을 함께 고칩니다.

- 에이전트를 모은 문서 맨 위 세션 표: 이름·역할·칸(번호와 이름)·세션 식별값·상태
- 각 `agents/<id>-adk/index.md` 의 "세션" 절

"세션" 절 틀:

```markdown
## 세션

- **서버**: <그룹 개발 서버 이름>
- **자리**: <도구 세션> → <작업 공간> → <탭> → 칸 `<칸>` (칸 이름 `<이름>-<역할>`)
- **세션 식별값**: `<식별값>`
- **시작**: <띄운 시각>, 역할 첫 지시 <보낸 시각>
- **작업 폴더**: <경로> (함께 쓰는 세션이 있으면 적음)
- **역할 문서 사본**: <서버 안 경로>
- **깨움·봇 연결**: <없음 또는 연결 방식>
```

칸 번호만 적지 말고 칸 이름과 세션 식별값을 같이 적습니다. 비밀값은 적지 않습니다.

## 5. 메신저 글 전달과 답글

- 봇 깨움 연결 전에는 세션이 메신저를 직접 보지 못합니다. 조정 역할이 그 역할에 관련된 글(지시·결정·질문)을 모아 세션에 넘겨 파악시킵니다.
- 원문을 그대로, 누가 언제 쓴 글인지와 함께 넘깁니다. 짧으면 한 줄 지시에 담고, 길면 역할 문서 사본 폴더에 파일로 두고 경로만 한 줄로 알립니다.
- 넘긴 글은 파악용입니다. "읽고 요약만, 행동은 지시가 온 뒤"를 함께 적습니다.
- 인사와 답글은 각 역할이 자기 봇으로 합니다. 다른 역할이나 다른 그룹의 봇으로 대신 쓰지 않습니다.

## 6. 지킬 것

- 여러 역할 세션이 같은 작업 폴더를 함께 쓰는 동안 지시 전에는 읽기만 합니다. 파일 수정·git·배포는 지시를 받은 세션만 합니다.
- 지시는 한 줄로 보냅니다. 여러 줄을 붙여 넣지 않습니다.
- 지시와 기록에 비밀값을 넣지 않습니다. 봇 열쇠는 매니페스트의 이름표(`bot.credential_ref`)로만 가리킵니다.
- 운영 서버 변경·결제·외부 발송은 사람 승인 뒤에만 합니다.
- 다른 그룹의 에이전트와 섞지 않습니다.

## 7. 아직 정하지 않은 것

1. 봇 깨움 연결: 메신저에 글이 오면 해당 역할 세션을 깨우는 연결 방식. 정해지면 매니페스트의 `bot.status` 를 `planned` 에서 `active` 로 바꿉니다.
2. 에이전트별 작업 폴더: 처음에는 여러 역할이 한 작업 폴더를 함께 쓸 수 있습니다. 역할마다 자기 자리(`agents/<id>-adk`, 에이전트 뼈대는 `templates/agent-skeleton/`)를 서버의 작업 폴더로 두고 역할 문서 사본을 그 안으로 옮기는 방식을 다음 판에서 정합니다. 네 갈래 뼈대와 연결은 [네 갈래 ADK 뼈대와 연결](adk-four-kinds.md)에 있습니다.

## 도구를 바꿔도 같은 역할로 이어가기

설치판 `config/work-ledger.json` 안에서 각 역할이 읽을 자리와 그룹을 지정합니다. 예를 들어 검수 역할의 설정은 다음과 같습니다.

```json
{
  "role": "reviewer",
  "handoff": {
    "workspace": "agents/reviewer-adk",
    "agent_id": "reviewer-adk",
    "session_dir": "sessions/reviewer",
    "group": "team",
    "notes": { "common": ["preferences.md"], "group": ["handoff.md"] },
    "claude_auto_memory": true
  }
}
```

역할 매니페스트 `adk.json`의 ID와 소속 그룹, 실제 세션 폴더가 설정과 일치해야 합니다. `session_dir`을 생략하면 에이전트 자리를 사용합니다. 설치판의 세션 관리자가 역할 폴더에서 `NAIA_ROLE=reviewer`를 지정해 세션을 시작합니다. 언급된 노트에는 역할 공통 선호와 현재 그룹의 기록을 각각 둡니다.

```bash
node scripts/adk-user-profile.mjs apply --adk-root "$runtime" --instance-root "$instance"
node scripts/adk-user-profile.mjs check --adk-root "$runtime" --instance-root "$instance"
```

Codex에서 새 사용자 훅을 등록하거나 정의가 바뀌면 `/hooks`에서 이 설치판의 `role-handoff.mjs` 명령과 위치를 검토하고 해당 훅을 신뢰합니다. 등록만 된 훅은 첫 입력에서 빠질 수 있습니다. [Codex 훅의 신뢰 설정](https://developers.openai.com/codex/hooks#review-and-trust-hooks)

Claude와 Codex의 세션 시작 훅은 같은 원본의 노트, 최근 미완료 카드 12개, 각 카드의 원글과 최근 일꾼 결과를 읽습니다. 같은 원본이면 인계문의 SHA-256도 같습니다. 새 카드는 등록 시 소유 그룹을 기록합니다. 기존 카드에는 그룹이 없을 수 있습니다. 해당 그룹 전용으로 확인한 원본 채널만 `legacy_card_channels`에 등록하면 그 채널의 기존 카드도 복원됩니다. 다른 세션 폴더와 하위 일꾼에는 역할 기억을 싣지 않습니다.

`claude_auto_memory`를 켜면 설치기가 해당 세션의 `.claude/settings.local.json`에 그룹 기억 폴더를 지정합니다. Claude가 저장하는 `MEMORY.md`를 Codex도 다음 기동 때 읽고, 두 도구가 같은 폴더의 주제 파일을 열 수 있습니다. 기존 Claude 전용 기록을 옮길 때는 해당 역할과 그룹에 속한다고 확인된 인덱스와 주제 파일만 이 폴더에 보관합니다. 한 저장소의 여러 작업 폴더는 Claude 기본 기억을 공유할 수 있습니다. [Claude Code 기억 저장 위치](https://code.claude.com/docs/en/memory#storage-location)

다른 CLI가 시작 훅을 지원하지 않으면 세션 시작기가 `node scripts/work-ledger/role-handoff.mjs "$instance" reviewer "$session_dir"`의 출력을 첫 입력으로 전달할 수 있습니다. 자동 연결이 된 설치판은 실제 이름표와 원글이 있는 카드를 만든 뒤, 같은 역할의 두 CLI에서 이어진 기록과 다른 역할에서 제외된 기록을 확인합니다.
