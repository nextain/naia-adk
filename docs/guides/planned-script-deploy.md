# Hash-bound deployment scripts

An instance can enable `plannedScripts` in `config/deploy-gate.json` with an exact service set, absolute script-directory `roots`, and `systemdUserUnits`. Set `allowSudo: true` only when the reviewed installation requires root; otherwise the exact `sudo bash` form is refused. The public example has this capability disabled. Instance paths, account names and actual service identifiers belong in the local configuration and immutable deployment plan. The classifier detects script paths under configured roots and conservatively gates every configured service, including runtime installation commands without a `prod` argument. Extra instance `prodPatterns` entries are unnecessary for this family.

Each scenario command must be exactly `bash /absolute/script.sh s0` (or a rollback `r0`), (optionally prefixed by exactly `sudo ` when configured), with its final argument equal to the unique scenario ID. Rollback entries require `branch: "rollback"`. The entry's `files` maps the script and every reviewed helper to their SHA-256 digests. Changed bytes, missing script pins, symlinked scripts, paths outside configured roots, shell prefixes, extra arguments and command chaining are rejected before plugin or custom-command fallbacks.

Literal units in direct `systemctl --user` and `userctl` wrapper calls must be registered. This is a target check, not a proof of arbitrary shell program behavior: independent plan review binds the whole script and helper bytes, including account restrictions and dynamic wrapper behavior. A successful binding does not authorize execution; readiness, plan review and human step approval remain required.

In this explicitly configured mode, `entry.files` is the complete reviewed input manifest. After script binding succeeds, the plan evaluator verifies every declared file directly instead of recursively guessing dependencies from arbitrary shell tokens. This avoids treating incidental text such as `README.md`, installed runtime executables or output destinations as deployment inputs. Reviewers must enumerate all mutable helpers and actual inputs; omitted dependencies are not discovered by a shell safety proof. Unconfigured legacy commands retain recursive reference checks.


The fixed `stopAllLockFile` in the checkout's `config/deploy-gate.json` is shared by mail and deployment consumers. It must match the application runtime contract; environment variables cannot override it. A missing setting uses `/var/lib/ax-shared/stop-all.lock`; unreadable files or malformed policy fail closed. Rollback readiness still requires the reviewed rollback plan and may run while locked.

Script classification checks both the attempted path and its real path. Symlinks pointing into registered roots remain gated, including links outside the roots. Binding rejects noncanonical paths, missing files, symlinks, and roots reached through symlinks. Read-only script inspection stays outside deployment classification.
