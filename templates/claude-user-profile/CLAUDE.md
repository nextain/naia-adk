# Compact instructions

요약의 목적: 요약 뒤 세션이 같은 미션을 드리프트 없이 이어 가게 하는 것. 요약은 짧게 하되, 아래 "반드시 남길 것"은 하나도 빠뜨리지 않는다.

## 원칙

1. 문서는 본문이 아니라 위치를 남긴다: 경로 + 한 줄 상태 + 다음에 볼 절. 본문은 압축 뒤 그 경로를 다시 읽는다.
2. 지시한 사람의 지시는 원문 그대로 인용한다. 바꿔 말하지 않는다. 나중 지시가 앞 지시를 정정했으면 정정된 쪽만 남기고 "정정됨"을 적는다.
3. 사실과 주장을 구분한다. 실물(파일·커밋·녹화·로그)로 확인한 것만 "확인됨", 작업자가 말만 한 것은 "주장, 미확인".
4. 끝난 일의 과정, 도구 출력 원문, 시행착오 서술은 버린다. 같은 실수를 막는 교훈만 한 줄로 남긴다.

## 반드시 남길 것 (이 순서, 이 제목으로)

1. 미션: 미션 원문 파일 경로, 현재 목표 한두 줄, 지시한 사람의 최근 원문 지시(시각 포함).
2. 작업 문서 목록: 표로 `경로 | 종류 | 상태 | 다음 행동`.
   - 종류: 미션 원문, 진행 기록, 보고서, 작업 지시서, 결과 문서, 검수 기록, 결정 기록, 세션 계약, 인계 문서
   - 지시서·결과는 실행자(일꾼·다른 세션 이름), 완료 주장 여부, 실물 확인 여부를 상태에 적는다.
   - 검수 기록은 회차와 남은 지적 수, 결정 기록은 결정 번호를 적는다.
3. 코드 상태: 저장소별 작업 가지, 작업 트리 경로, 기준 커밋, 내 커밋(푸시 여부), 아직 커밋 안 한 변경.
4. 돌아가는 것: 백그라운드 작업·다른 세션·GPU 작업마다 무엇을 기다리는지, 로그·결과 파일 경로, 끝났는지 확인하는 방법.
5. 남은 할 일: 순서와 의존 관계, 사람 승인이 필요한 것 표시.
6. 지킬 것: 이번 미션에서 나온 금지 사항과 정정된 실수(한 줄씩).

## 압축 뒤 첫 행동

미션 원문 파일 → 진행 기록 끝부분 → 보고서 순으로 다시 읽고, "돌아가는 것"의 결과부터 확인한 뒤 이어서 진행한다. 지시한 사람에게 다시 묻지 않는다.

# 컨텍스트 절약

- 코드베이스 탐색, 로그 분석, 시험 실행은 서브에이전트나 일회성 호출에 맡기고 결론만 받는다.
- 긴 출력은 잘라서 읽는다. 기다리기·지켜보기는 스크립트로 하고 중간에 조회하지 않는다.
